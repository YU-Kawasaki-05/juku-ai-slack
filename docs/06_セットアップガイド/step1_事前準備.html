STEP 1 — 事前準備（決めること）

このステップではまだ何も作りません。後で変えると作り直しになる項目を先に決めます。 特に「Embedding の次元」と「チャンネルを公開／非公開のどちらにするか」は、あとから変えると DB とスコープをやり直すことになります。

所要時間約 30 分
このステップで手に入るもの
  • LLM の API キー / Base URL / モデル名（2 種）
  • Embedding の API キー / Base URL / モデル名
  • チャンネル公開方針（→ Slack スコープが決まる）
  • 月額コストの見積り

1-1. LLM プロバイダを決める

じゅくAI はプロバイダ非依存です。OpenAI 互換の POST /chat/completions を話せるサービスなら、環境変数の差し替えだけで切り替わります （実装: src/features/ai-answer/lib/llm/openaiCompatibleClient.ts、公式 openai SDK に baseURL を渡しているだけ）。

候補LLM_BASE_URLモデル名の例向いているケース
OpenAIhttps://api.openai.com/v1gpt-4o-mini / gpt-4o実績重視。Vision（画像）も同じキーで使える。Embedding も同居できる
OpenRouterhttps://openrouter.ai/api/v1deepseek/deepseek-chat
openai/gpt-4o		1 つのキーで複数ベンダーを試せる。モデル名は provider/model 形式
DeepSeekhttps://api.deepseek.comdeepseek-chat最安。ただし画像（Vision）非対応なので LLM_MODEL_COMPLEX は別プロバイダにする

モデルは 2 つ設定する

環境変数いつ使われるか未設定だと
LLM_MODEL_DEFAULT通常の質問すべて。スレッド要約・生徒回答の評価（BKT）にもこれを使う回答不可。ConfigurationError（LLM_MODEL_DEFAULT が未設定です）でジョブが失敗する（リトライしても直らない）
LLM_MODEL_COMPLEX画像が添付された質問のみ画像は LLM に送らずテキストのみで回答する。生徒には「画像は読み取れなかった」旨を添え、運用者向けには IMAGE_MODEL_NOT_CONFIGURED をエラーログに残す。画像対応するなら設定する

根拠: src/features/jobs/lib/executeProcessMessage.ts （const useModel = imageDataUrls.length > 0 ? (env.LLM_MODEL_COMPLEX ?? model) : model）

重要: モデル名を MODEL_PRICING に登録しないとコストが 0 円表示になる

コストは「プロバイダの請求額」ではなく、アプリ内の単価表から計算しています。 src/shared/lib/constants.ts の MODEL_PRICING に載っていないモデル名を使うと、 トークン数は記録されるのに 推定コストが 0 で記録され、/admin の「今月のコスト」が 0 のまま増えません。

初期状態で登録済みのモデルは次のとおりです（USD / 100 万トークン）。

モデル名（キー）入力出力
claude-haiku-4-5 / anthropic/claude-haiku-4-5$1.00$5.00
claude-sonnet-4-6 / anthropic/claude-sonnet-4-6$3.00$15.00
gpt-4o-mini / openai/gpt-4o-mini$0.15$0.60
gpt-4o / openai/gpt-4o$2.50$10.00
deepseek-chat / deepseek/deepseek-chat$0.27$1.10

照合ルール（findModelPrice）: まず完全一致、次に / 以降のサフィックスで再照合します。 つまり deepseek-chat さえ登録されていれば、openrouter/deepseek-chat のような未登録キーでもヒットします。 逆に、素の名前もサフィックスも登録がなければ 0 円になります。

登録されていないモデルを使う場合

使うモデル名と単価を MODEL_PRICING に追記してから STEP 5 のデプロイに進んでください（コード変更 → 再デプロイが必要）。

// src/shared/lib/constants.ts

const PRICE_MY_MODEL: ModelPrice = { inputPerM: <入力単価USD>, outputPerM: <出力単価USD> }

export const MODEL_PRICING: Record<string, ModelPrice> = {
  // ...既存...
  '<素のモデル名>': PRICE_MY_MODEL,
  '<provider>/<素のモデル名>': PRICE_MY_MODEL,
}

1-2. Embedding プロバイダを決める

1536 次元のモデルしか使えません。 DB のカラムが vector(1536) 固定（migration 005 / 020）で、 コード側も EMBEDDING_DIM = 1536 と突き合わせています。次元が違うと保存時に例外になります:

embedding dimension mismatch: model "<モデル名>" returned 3072 dims,
expected 1536. EMBEDDING_MODEL の設定を見直してください
モデル次元可否
text-embedding-3-small（OpenAI）1536推奨
text-embedding-ada-002（OpenAI・旧世代）1536使える
text-embedding-3-large（OpenAI）3072そのままでは不可（dimensions パラメータ指定は未実装）

未設定でも動きます（RAG が無効になるだけ）。 EMBEDDING_* が未設定だと EmbeddingNotConfiguredError（severity=info）となり、 Bot はレポートを参照せずに回答します。エラーログには積まれません（毎メッセージで洪水にならないよう意図的に抑制）。 ただしレポートを AI に読ませたいなら必須です。

LLM に OpenRouter や DeepSeek を選んでも、Embedding だけ OpenAI にする構成で問題ありません（EMBEDDING_BASE_URL は独立した設定です）。

1-3. 生徒チャンネルを公開／非公開のどちらにするか

この選択で Slack に必要なスコープと購読イベントが変わります。後から変えるとアプリの再インストールが必要です。

方式チャンネル ID必要な追加スコープ購読する bot event特徴
公開チャンネル
（#taro-juku など）		C で始まるchannels:historymessage.channelsワークスペースの他メンバーも中身を見られる。スタッフの巡回は楽
非公開チャンネル
（🔒 付き）		G または C で始まる（近年の Slack は非公開でも C のことがある）groups:history
（channels:history と併用可）		message.groups招待した人しか見られない。生徒の相談内容が他生徒に見えない

迷ったら「非公開チャンネル」を推奨します。学習の相談は個人情報に近く、ワークスペース内の他生徒・他保護者に見えると事故になります。 その場合、STEP 4 では channels:history と groups:history の両方、STEP 6 では message.channels と message.groups の両方を入れておくと、後から公開チャンネルを足しても再設定が不要です。

紐付け登録のバリデーションは /^[CGD][A-Z0-9]+$/ なので、公開・非公開のどちらでも登録できます（src/features/channel-bindings/schemas/bindingSchema.ts）。

1-4. Supabase / Vercel のプランを決める

サービス推奨プラン推奨理由（このアプリ固有）
SupabasePro（$25/月）
  • Free は 1 週間アクセスがないとプロジェクトが一時停止する。止まると Slack 側の Bot が全生徒に対して無応答になる（休み明けに事故る）
  • 添付画像を attachments バケットに保存する。1 枚最大 20MB、1 メッセージ最大 3 枚。Free のストレージ枠（1GB）はすぐ埋まる
  • 自動バックアップ（日次・7 日保持）が付く。Free にはバックアップがない
VercelPro（$20/月）
  • これが本命の理由。/api/slack/events は maxDuration = 300（5 分）を宣言している。Hobby プランの上限は 60 秒なので、LLM 生成が長引くと関数が途中で kill され、🤔 が付いたまま回答が返らず、ジョブが processing のまま残る
  • 商用利用は Vercel の規約上 Pro 以上が必要

根拠: src/app/api/slack/events/route.ts の export const maxDuration = 300。 コメントにも「after() 内の AI 処理は既定の実行時間上限に収まらない。kill されると jobs が processing のまま残り、🤔 も消えず生徒には無応答になる」とあります。

1-5. 月額コストの見積り

1 質問あたりに走る API 呼び出し

#呼び出しいつコスト記録
1Embedding（質問文のベクトル化）毎回（EMBEDDING_* 設定時）記録されない
2LLM: Tutor（回答生成）毎回ai_usage_logs に記録
3LLM: スレッド要約未要約メッセージが 20 件たまったとき（= 約 10 往復ごとに 1 回）ai_usage_logs に記録
（message_ts が -summary で終わる行）
4LLM: Evaluator（生徒の返答を採点して習熟度を更新）現状は起動しません（socratic / confirmation モード専用。現行の実装は常に direct モードで応答するため）起動時のみ記録
（-eval 行）

つまり現状は 1 質問 = Embedding 1 回 + LLM 1 回、これに約 10 往復ごとに要約の LLM 1 回が上乗せされます。 要約は 400 トークン上限なので、質問 1 回ぶんより安く済みます。

要約とEvaluator の呼び出しは、生徒 1 人あたりのレート制限（後述の 10 回/時）にはカウントされません （集計時に -summary / -eval の行を除外しているため）。

Embedding のコストは管理画面に出ません。logUsage は LLM 呼び出しでしか呼ばれていないためです。 金額としては微小（text-embedding-3-small で 100 万トークン $0.02）ですが、 実額の確認はプロバイダのダッシュボードで行ってください。

概算（生徒 50 名 × 月 20 質問 = 月 1,000 質問）

前提: 1 質問あたり入力 約 4,000 トークン（システムプロンプト + 生徒プロフィール + RAG チャンク最大 5 件 + 履歴 + 質問）、出力 約 500 トークン、 スレッド要約のぶんを上乗せ。1 USD = 150 円。あくまで桁感の目安です。

使うモデル1 質問あたり月 1,000 質問+ Supabase Pro + Vercel Pro合計（円）
gpt-4o-mini約 $0.0011約 $1.1$45約 7,000 円
deepseek-chat約 $0.0020約 $2.0$45約 7,100 円
claude-haiku-4-5約 $0.0070約 $7.0$45約 7,800 円
gpt-4o約 $0.0180約 $18$45約 9,500 円

読み取り方: この規模だと インフラ固定費（$45 ≒ 6,750 円）が支配的で、LLM 代はモデルを変えても数百〜数千円の差です。 「安いモデルにする」より「生徒数が増えたとき」に効いてきます。生徒 200 名・月 8,000 質問なら LLM 代は上表の 8 倍になります。

コストが暴れないための歯止め（実装済み）

  • レート制限: 生徒 1 人あたり 直近 1 時間で 10 質問まで。超過分は LLM を呼ぶ前に定型文で返すので課金されません（RATE_LIMIT_QUESTIONS_PER_HOUR）
  • 質問文の上限: 6,000 文字を超える質問は LLM 呼び出し前に打ち切り（MAX_QUESTION_CHARS）
  • 出力上限: 回答 1,200 トークン / 要約 400 トークン
  • 画像の上限: 1 枚 20MB・1 メッセージ 3 枚・合計 8MB まで
  • 画像の解像度上限: 長辺 2048px を超える画像は送信前に自動縮小（MAX_IMAGE_LONG_EDGE）。画像のトークン数はピクセル数に比例するため、これが 1 枚あたりのコストの天井になります（縮小しない画像は一切加工しません）
  • 緊急停止: 管理画面から AI 応答を即停止できる（デプロイ不要 → STEP 9）
  • 再試行での二重課金なし: 生成済みの回答本文は保存され、リトライ時は配信のみやり直す

画像付き質問は別枠で高い

画像は base64 化して LLM_MODEL_COMPLEX に送ります。長辺 2048px にキャップした状態で 1 枚あたり最大 約 5,000 入力トークン相当が上乗せされ、さらに Vision 対応モデルは単価が高めです。 画像利用が多い想定なら、テキストは安いモデル・画像は gpt-4o という組み合わせが現実的です。
