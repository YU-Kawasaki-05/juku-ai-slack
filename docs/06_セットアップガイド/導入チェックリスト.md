# 塾を1件導入する — 作業者用チェックリスト（1枚）

> 対象読者: **導入する側（開発者）**。塾のスタッフ向けは `docs/08_スタッフマニュアル/` が別にある。
> 詳しい画面つきの手順は `docs/06_セットアップガイド/step1〜9`。このページはその**索引と検算**。

現状は **1デプロイ = 1塾**（テナント分離は無い）。2社目は、この手順をもう一度なぞって
別の Supabase プロジェクト + 別の Vercel プロジェクトを立てる。

## 最後に必ずこれを叩く

```
pnpm check:deployment -- --app-url https://<その塾のドメイン>
```

**書き込みは一切しない。** 環境変数・Supabase・Slack・LLM・アプリ・招待リンクを
横断して読み、「塾で使える状態か」を判定する。NG が 0 になるまで潰す。

なぜ手順書だけでは足りないか:

> **この製品の失敗は、ほぼ全部が静かに起きる。**
> Redirect URLs の未登録も、LLM キーの未設定も、マイグレーションの流し漏れも、
> どれもビルドを通り、デプロイも成功し、**生徒が最初の質問を投げた瞬間に初めて露見する**。
> 手順を「やった」ことと、環境が「動く」ことは別なので、最後に機械で検算する。

補足で使う個別のコマンド:

```
pnpm check:invite-redirect -- --app-url https://<ドメイン>   # 招待リンクの着地先だけ見る
pnpm check:grades                                            # 学年欄に氏名が混入していないか
pnpm slack:preview                                           # Slack 出力の整形結果を目で見る
```

## 環境変数（正本は `src/shared/lib/env.ts`）

**「ビルドに要る」と「塾で使えるのに要る」は違う。** ここを混ぜると事故る。

- `env.ts` の zod スキーマで**必須は6項目だけ**。`LLM_API_KEY` などが optional なのは、
  未設定でもビルドと他機能を壊さないための意図的な設計。
- つまり **env のパースを通っても、質問に1件も答えられない環境が作れてしまう。**
- `check:deployment` は後者の基準（塾で使えるか）で判定し、**9項目を必須**として扱う。

| 区分 | 項目 |
|---|---|
| 必須（9） | `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY` / `SLACK_BOT_TOKEN` / `SLACK_SIGNING_SECRET` / `SLACK_BOT_USER_ID` / `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL_DEFAULT` |
| 推奨（6） | `LLM_MODEL_COMPLEX`（画像を読む）/ `EMBEDDING_API_KEY`・`EMBEDDING_BASE_URL`・`EMBEDDING_MODEL`（レポート検索）/ `SLACK_ALERTS_CHANNEL_ID`（緊急停止の通知先）/ `SLACK_WORKSPACE_URL` |
| 未使用（4） | `SLACK_API_BASE_URL`（テスト用）/ `ANTHROPIC_API_KEY` / `RESEND_API_KEY` / `RESEND_FROM_EMAIL`（保護者メールは未実装） |

`APP_URL` は `.env.local` には入っていないので、`invite-staff.mjs` と `check-deployment.mjs` には
`--app-url` を毎回渡すか、環境変数に足しておく。

## 踏みやすい落とし穴（実際に踏んだもの）

- **Redirect URLs に `/set-password` を登録し忘れる。** エラーにならず Site URL に着地する。
  スタッフからは「リンクを開いたのにパスワードを設定できない」としか見えない。
- **`localhost` はループバック判定を通らない。** ローカル検証は `http://127.0.0.1:3000` と書く。
- **招待リンクは60分・1回限り。** 切れたら `--reissue-only` で再発行する（ユーザーは作り直さない）。
- **学年欄は外部の LLM に送られる。** 氏名は送らない設計なので、学年欄に「中3 山田」と
  書かれると氏名だけが外へ出る。`pnpm check:grades` で点検する。
- **`SLACK_BOT_USER_ID` がトークンの実体とズレる。** 自分の投稿に反応して往復する事故になりうる。
  `check:deployment` が `auth.test` の `user_id` と突き合わせる。
