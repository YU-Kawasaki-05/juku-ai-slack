STEP 4 — Slack アプリ作成

塾の Slack ワークスペースに Bot を作ります。この時点では Event Subscriptions（イベント購読）は設定しません。 アプリがまだデプロイされていないため、Slack が Request URL を検証しに来ても応答できず、設定が保存できないからです。

所要時間約 20 分
前提塾の Slack ワークスペースにアプリを追加できる権限
このステップで手に入るもの（控える）
  • Bot User OAuth Token（xoxb-...）
  • Signing Secret
  • Bot User ID（U...）
  • Team ID（T...）

4-1. 必要なスコープと、その根拠

このアプリが Slack Web API に投げるメソッドは 3 つだけ（chat.postMessage / reactions.add / reactions.remove）で、 あとは Events API の受信と、画像ファイルの直接ダウンロードです。必要なのは次の 5 スコープです。

スコープ用途これが無いと何が壊れるか根拠（コード）
chat:write
必須		 AI 回答・エラー案内文・kill switch の #alerts 通知を投稿する 質問しても何も返らない。chat.postMessage failed: not_in_channel 等 src/shared/lib/slack/client.ts の postMessage()
reactions:write
必須		 処理中を示す 🤔（thinking_face）の付与と、回答後の除去 回答は返るが 🤔 が付かない。生徒に「受け付けた」感が伝わらない。
※リアクション失敗はサイレント処理なので、Slack 上は無症状。サーバーログに [slack] reactions.add failed: missing_scope が出る		 addReaction() / removeReaction()、THINKING_REACTION = 'thinking_face'
channels:history
公開なら必須		 公開チャンネルの message.channels イベント（本文・添付ファイル情報を含む）を受け取る イベントが一切届かない。Bot は完全に無反応 src/app/api/slack/events/route.ts（event.type === 'message' のみ処理）
groups:history
非公開なら必須		 非公開チャンネルの message.groups イベントを受け取る 非公開チャンネルからのイベントが届かない 同上（イベント種別が違うだけで処理は共通）
files:read
必須		 Slack の url_private から Bot トークンで画像本体をダウンロードする 画像付き質問で SLACK_FILE_DOWNLOAD_FAILED。画像だけを送った質問には 「画像の取得に失敗しちゃった …」と返り、本文がある質問では画像だけが黙って無視される（テキストのみで回答してしまう） src/features/image-attachments/lib/downloadSlackFile.ts

入れなくてよいスコープ（よく間違えるもの）

スコープ不要な理由
channels:read / groups:read conversations.list や conversations.info を一度も呼んでいません。 チャンネル名は管理画面で手入力する表示用の値で、判定には使いません（信頼の基点は channel_id）
users:read users.info を呼んでいません。「誰の質問か」は channel_id → 紐付けテーブルから決まります。 イベントの user フィールドは認可に使っていません（なりすまし対策）
app_mentions:read app_mention イベントを購読しません。受信ハンドラは event.type !== 'message' を即座に無視するため、 購読しても捨てられるだけです。メンション判定は message イベント本文の <@BotUserID> を自前で見ています
chat:write.public Bot を各チャンネルに /invite する運用なので不要です
im:history / mpim:history DM 運用はしません（紐付けは生徒専用チャンネル単位）

4-2. 方法A: manifest から作る（推奨）

  1. https://api.slack.com/apps → Create New App
  2. From an app manifest を選択
  3. 塾のワークスペースを選択 → Next
  4. YAML タブを選び、下の manifest を貼り付ける → Next → Create

manifest（そのままコピーして使えます）

display_information:
  name: じゅくAI
  description: 生徒ごとのチャンネルで学習の質問に答える AI アシスタント
  background_color: "#2b3a55"
  long_description: 生徒ごとの Slack チャンネルで、学習レポートや過去のやり取りを踏まえて質問に答える AI 学習支援ボットです。メンションまたはスレッド返信に反応し、処理中は :thinking_face: を付けます。

features:
  bot_user:
    display_name: じゅくAI
    always_online: true

oauth_config:
  scopes:
    bot:
      # 回答・案内文・運用アラートの投稿（chat.postMessage）
      - chat:write
      # 処理中を示す :thinking_face: の付け外し（reactions.add / reactions.remove）
      - reactions:write
      # 公開チャンネルの message.channels イベント受信
      - channels:history
      # 非公開チャンネルの message.groups イベント受信（非公開運用なら必須）
      - groups:history
      # 添付画像を url_private からダウンロードする
      - files:read

settings:
  # Event Subscriptions は STEP 6 で追加する（今 request_url を書くと検証に失敗して作成できない）
  org_deploy_enabled: false
  socket_mode_enabled: false
  token_rotation_enabled: false
  is_hosted: false

なぜ manifest に event_subscriptions を書かないのか

Slack は request_url を保存する瞬間に、その URL へ type: "url_verification" の チャレンジ POST を投げて 3 秒以内の応答を要求します。 アプリがまだ Vercel にデプロイされていない（= 404）、あるいは SLACK_SIGNING_SECRET が未設定で 起動時バリデーションに落ちている（= 500）状態では検証に失敗し、 manifest のインポート自体がエラーになります。 先にアプリを作って Signing Secret を取り、STEP 5 でデプロイしてから STEP 6 で URL を登録する、という順番が必要です。

公開チャンネルしか使わないと決めている場合は groups:history を外しても構いませんが、 後から非公開チャンネルを足すときにスコープ追加＋再インストールが必要になります。両方入れておく方が運用は楽です。

4-3. 方法B: From scratch で作る

manifest を使わない場合の手順です（結果は同じ）。

  1. Create New App → From scratch
  2. App Name = じゅくAI、ワークスペースを選択 → Create App
  3. 左メニュー OAuth & Permissions → Scopes → Bot Token Scopes → Add an OAuth Scope で 5 つ（chat:write / reactions:write / channels:history / groups:history / files:read）を追加
  4. 左メニュー App Home → App Display Name の Edit で表示名を設定
    ※ Bot User が作られていない場合は、ここで作成されます
  5. 左メニュー Basic Information → Display Information でアイコン・色を設定（任意）

4-4. ワークスペースにインストールする

  1. 左メニュー OAuth & Permissions → Install to <ワークスペース名>
  2. 権限の確認画面 → 許可する

インストール後、Bot User OAuth Token（xoxb- で始まる）が表示されます。控えてください。 これが環境変数 SLACK_BOT_TOKEN になります。

4-5. Signing Secret を取得する

  1. 左メニュー Basic Information → App Credentials
  2. Signing Secret の Show をクリックして表示 → 控える

これが環境変数 SLACK_SIGNING_SECRET です。 受信した Webhook が本当に Slack から来たものかを HMAC-SHA256 で検証するのに使います（合わないと 401 を返します）。

Signing Secret と Bot Token は同じくらい重要な機密です。 Bot Token が漏れると塾のワークスペースに任意の投稿ができ、生徒が送った画像もダウンロードできてしまいます。 漏洩時は Basic Information → App Credentials → Regenerate（Signing Secret）と、 OAuth & Permissions → Revoke / 再インストール（Bot Token）で差し替えてください。

4-6. Bot User ID を取得する

ここが一番間違えやすい箇所です。必要なのは U で始まる Bot User ID であって、 B で始まる Bot ID ではありません。B... を設定すると メンション検出が一致せず、Bot が永久に無反応になります（エラーも出ません）。

方法1: auth.test を叩く（確実・推奨）

curl -s -H "Authorization: Bearer xoxb-<あなたのBotToken>" \
  https://slack.com/api/auth.test

返ってくる JSON:

{
  "ok": true,
  "url": "https://<ワークスペース>.slack.com/",
  "team": "<ワークスペース名>",
  "user": "じゅくai",
  "team_id": "T01ABCDEFGH",     ← STEP 7 のチャンネル紐付けで使う
  "user_id": "U01ABCDEFGH",     ← これが SLACK_BOT_USER_ID
  "bot_id": "B01ABCDEFGH"       ← これではない
}
フィールド控える先
user_id（U 始まり）環境変数 SLACK_BOT_USER_ID
team_id（T 始まり）STEP 7 のチャンネル紐付けフォームの「ワークスペース ID」
url環境変数 SLACK_WORKSPACE_URL（任意。管理画面から Slack スレッドへのリンクに使う）

auth.test の呼び出しに追加スコープは不要です。"ok": false が返る場合はトークンのコピーミス （xoxb- の前後に空白が入っていないか、User Token xoxp- と取り違えていないか）を確認してください。

方法2: Slack クライアントから調べる

  1. Slack で任意のチャンネルのメンバー一覧、または検索窓から じゅくAI を開く
  2. プロフィールの 「…」（その他） → メンバー ID をコピー

この方法でも U 始まりの ID が得られます。ただし表示名が似た別ユーザーを開いてしまう事故があるため、方法1 を推奨します。

4-7. この時点での状態

Slack アプリはできましたが、まだイベントは届きません（購読していないため）。 生徒チャンネルへの招待も STEP 7 で行います。ここで一度、控えた値を確認してください。

控えた値形式の例環境変数名
Bot User OAuth Tokenxoxb-1234567890-...SLACK_BOT_TOKEN
Signing Secret32 桁の英数字SLACK_SIGNING_SECRET
Bot User IDU01ABCDEFGHSLACK_BOT_USER_ID
Team IDT01ABCDEFGH（環境変数ではない。STEP 7 のフォームで使う）
ワークスペース URLhttps://xxx.slack.comSLACK_WORKSPACE_URL（任意）
