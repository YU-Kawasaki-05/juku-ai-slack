トラブルシューティング

症状から原因を引くための早見表です。まず下の「切り分けの順番」を上から確認すると、たいていの問題は 5 分で場所が特定できます。

Slack の Request URL が Verified にならない

詳細な原因表は STEP 6-2 にあります。要点だけ再掲します。

原因見分け方対処
SLACK_SIGNING_SECRET の未設定・不一致
最頻出		 Vercel の Runtime Logs に [slack/events] signature verification failed: 値を再コピーして Vercel に設定 → 再デプロイ。Client Secret や Verification Token と取り違えていないか確認
URL の綴り誤りブラウザで開くと 404https://<ドメイン>/api/slack/events（末尾スラッシュなし）。GET で 405 が返ればパスは正しい
別の環境変数の形式エラー/login も 500。ログに Missing or invalid env vars:env は一括検証されるため無関係な 1 個で全滅する。空文字で登録した任意変数は行ごと削除
プレビュー URL を登録したURL に -git- が入っているProduction ドメインに変更
Deployment Protection本番でも 401 の HTML が返るVercel → Settings → Deployment Protection を解除

Bot が反応しない（🤔 も付かない）

頻度順に並べています。上から潰してください。

#原因見分け方対処
1 Bot がチャンネルに招待されていない
最頻出		 チャンネル詳細 → インテグレーション にアプリが無い。 エラーログには何も出ない（Slack がイベントを送っていないため） チャンネルで /invite @じゅくAI
2 メンションしていない チャンネル直下でメンション無しに発言している チャンネル直下では @じゅくAI が必須。ただし Bot が一度答えたスレッドの中ではメンション不要
3 SLACK_BOT_USER_ID が間違っている B で始まる値を入れている。エラーは一切出ず、完全な無反応になる curl -H "Authorization: Bearer xoxb-..." https://slack.com/api/auth.test の user_id（U 始まり）に修正 → 再デプロイ
4 チャンネルが紐付けされていない メンションすると このチャンネルにはまだBotの設定が完了していないみたい。… と返る STEP 7-8 で紐付けを登録。この案内が返るならイベント経路は正常
5 生徒が「無効」になっている 完全に沈黙する（案内文すら出ない）。/admin/errors を深刻度すべてにすると PERSON_INACTIVE（情報）がある 生徒管理 → ステータスを 有効 に
6 チャンネル紐付けが「無効」 案内文（CHANNEL_NOT_BOUND）が返る チャンネル設定 → ステータスを 有効 に
7 AI 応答が緊急停止中 いまメンテナンス中でお返事ができないんだ… が返る。/admin のカードが赤 AI応答を再開
8 レート制限に到達 今日はたくさん質問してくれてありがとう！… が返る 1 時間待つ。仕様（STEP 9-2）
9 イベント購読の設定漏れ Slack アプリの Event Subscriptions に message.channels が無い。 非公開チャンネルなのに message.groups が無いのもよくある 購読を追加 → Save Changes → アプリを再インストール
10 スコープ変更後に再インストールしていない Slack アプリ画面上部に黄色い警告バナーが残っている OAuth & Permissions → Reinstall to workspace
11 Bot 自身の投稿・システムメッセージに反応させようとしている 参加通知やピン留めなどに反応しない 仕様。Bot の発言と、ファイル共有以外の subtype 付きメッセージは無視されます

Slack 側が届けているかを確かめる決定打: Slack アプリ管理画面 → Event Subscriptions の Request URL 横にある Retry（または再度 URL を保存）で Verified を取り直しつつ、 Vercel の Logs に /api/slack/events のリクエストが記録されるかを見ます。 ログに何も出ない = Slack が送っていない（＝ 招待漏れか購読漏れ）。 ログに出ているのに無反応 = アプリ側の判定で無視されている（＝ 紐付け・無効・メンション）。

🤔 は付くが回答が返らない / 遅い

症状原因対処
🤔 が付いたまま数分〜永久に返らない 関数が実行時間の上限で強制終了された。/admin/jobs で 処理中 が滞留しているのが特徴 Vercel のプランを確認（Hobby は 60 秒上限、このアプリは 300 秒を宣言）。 Pro でも起きるなら軽いモデルに変更。滞留ジョブは スイープ実行 で回収し、再実行 で救済
30 秒以上かかる モデルが重い / RAG のチャンクが多い / プロバイダが混雑 まずは /admin/usage の モデル別 で使用モデルを確認。 gpt-4o のような重量級を常用モデルにしていないか
ときどき失敗して数十秒後に返る プロバイダの 429。5 秒 → 15 秒 → 45 秒でリトライしている /admin/errors に AI_RATE_LIMITED。頻発するならプラン引き上げ
回答の生成に時間がかかりすぎてしまった。… が返る AI_TIMEOUT 質問が長すぎるか、モデルが遅い。6,000 文字を超える質問は別途 TOKEN_BUDGET_EXCEEDED で弾かれる
うまく処理できなかったみたい… が返る AI_RESPONSE_FAILED。LLM 呼び出しの失敗 詳細ページの「内部エラー詳細」を確認。API キー失効・残高切れ・モデル名の誤り・LLM_MODEL_DEFAULT 未設定が典型

LLM_MODEL_DEFAULT が未設定だとリトライしても直りません（設定不備は再試行不能な失敗として扱われます）。 ConfigurationError: LLM_MODEL_DEFAULT が未設定です が内部詳細に出ていたら、環境変数を設定して再デプロイしてください。

コストが 0 円のまま増えない

ほぼ確実に MODEL_PRICING にモデル名が登録されていません。

確認判定
/admin/usage の 質問数 と 総トークン 増えているのにコストだけ 0 → 単価未登録で確定
すべて 0そもそも LLM が呼ばれていない。Bot が反応しないを参照
/admin/usage の モデル別 利用回数 そこに出ているモデル名が、MODEL_PRICING に登録済みかを確認する

対処

  1. src/shared/lib/constants.ts の MODEL_PRICING に、使っているモデル名と単価を追記する
  2. コミットして再デプロイ
const PRICE_MY_MODEL: ModelPrice = { inputPerM: <入力単価USD>, outputPerM: <出力単価USD> }

export const MODEL_PRICING: Record<string, ModelPrice> = {
  // ...既存...
  '<素のモデル名>': PRICE_MY_MODEL,
  '<provider>/<素のモデル名>': PRICE_MY_MODEL,
}

照合は「完全一致 → / 以降のサフィックス」の順です。deepseek-chat さえ登録してあれば openrouter/deepseek-chat でもヒットします。

すでに記録済みのログは 0 のままです。さかのぼって再計算されないため、 単価表の修正は気づいた時点ですぐ行ってください。

なお Embedding のコストは元から記録対象外です（LLM 呼び出しのみ記録）。 金額は微小ですが、実額はプロバイダのダッシュボードで確認してください。

レポートに Embedding の警告が出る

症状: レポート詳細ページに Embedding 再生成が必要です のバナー、 または保存時に 保存しました（AI 参照データは未更新） のトースト。 レポートの保存自体は成功していますが、AI はその内容を参照できません。

原因見分け方対処
EMBEDDING_* の設定漏れ 3 つ（EMBEDDING_API_KEY / EMBEDDING_BASE_URL / EMBEDDING_MODEL）のうち1 つでも欠けている 3 つセットで設定 → 再デプロイ。1 つでも欠けると RAG ごと無効になります
次元が 1536 でない 内部エラーに embedding dimension mismatch: … returned 3072 dims, expected 1536 text-embedding-3-small など1536 次元のモデルに変更。 text-embedding-3-large（3072 次元）は使えません
API キーの残高切れ・権限不足内部エラーに 401 / 429プロバイダ側で確認
本文を編集しただけで再生成していない 過去に生成できていたのにバナーが出た 本文を変更して保存すれば自動で再生成されます。失敗が続く場合のみ手動再生成

直したあと

レポート詳細ページの Embedding 再生成 ボタン（管理者のみ）で作り直します。 Embedding 再生成は管理者のみ実行できます と出る場合は、 role を admin にして再ログインしてください。

Embedding が無くても Bot は動きます。レポートを参照せず、プロフィールと会話履歴だけで回答します。 エラーログにも残りません（毎メッセージで洪水にならないよう意図的に抑制しています）。 「レポートの内容を反映してくれない」という相談は、まずここを疑ってください。

画像が無視される / 画像の質問に答えてくれない

原因見分け方対処
LLM_MODEL_COMPLEX が未設定
最頻出		 回答が画像に触れず一般論になる。エラーは一切出ない。 Vercel の Logs に 画像ありだが LLM_MODEL_COMPLEX 未設定 の警告 Vision 対応モデル（例 gpt-4o）を LLM_MODEL_COMPLEX に設定 → 再デプロイ
指定モデルが Vision 非対応 設定はしてあるが、そのモデルが画像を扱えない（deepseek-chat など） Vision 対応モデルに変更。テキストは安いモデル・画像だけ高性能モデル、という使い分けが可能です
files:read スコープが無い /admin/errors に SLACK_FILE_DOWNLOAD_FAILED スコープを追加 → アプリを再インストール
4 枚目以降を送っている 1 メッセージ 3 枚まで。4 枚目以降は黙って捨てられる（通知なし） 3 枚以内に分けて送る
サイズ超過 1 枚 20MB / 合計 8MB を超えている 圧縮して送り直す。画像のみの投稿なら 画像が少し大きすぎたみたい。… が返る
対応外の形式 HEIC・PDF・GIF など JPEG / PNG / WebP のみ対応。iPhone の HEIC は設定で JPEG 保存に変えるか、変換して送る

本文がある質問では、画像の失敗は生徒に伝わりません（テキストだけで回答してしまいます）。 「画像を見てくれない」という相談があったら、生徒の体感より /admin/errors と Vercel のログを見てください。

管理画面が 500 になる / 開けない

原因見分け方対処
環境変数の形式エラー
最頻出		 Vercel の Runtime Logs に Missing or invalid env vars: <変数名> 該当変数を修正。使わない任意変数を空文字で登録しているのが典型なので、その場合は行ごと削除する。 *_BASE_URL と NEXT_PUBLIC_SUPABASE_URL は URL 形式、RESEND_FROM_EMAIL はメール形式が必須
Supabase プロジェクトの一時停止 Free プランで 1 週間アクセスが無かった Supabase ダッシュボードから復帰。本番は Pro プラン推奨
Service Role キーのローテート漏れ Supabase でキーを再生成したのに Vercel が古いまま SUPABASE_SERVICE_ROLE_KEY を更新 → 再デプロイ

ログインできない

メッセージ原因対処
メールアドレスまたはパスワードが正しくありません。 認証情報の誤り、またはメール未確認 Supabase → Authentication → Users で Confirmed を確認。 ユーザー作成時に Auto Confirm User を入れ忘れているケースが多い。パスワードは Reset password で再設定
ログイン処理でエラーが発生しました。時間をおいて再度お試しください。 レート制限・ネットワーク・サーバー側エラー少し待つ。続くなら Runtime Logs を確認
ログインできるのに管理画面が使えない
「このアカウントには管理画面の利用権限が設定されていません」
（/admin/no-access）が表示される		 app_metadata.role が未設定（staff / admin のどちらでもない） ログイン自体は成功しているので、パスワードの再設定では直りません。SQL Editor で付与し、ログアウト → 再ログインします。 
update auth.users
set raw_app_meta_data = raw_app_meta_data || '{"role":"staff"}'::jsonb
where email = '<対象のメールアドレス>';
自分自身は admin にしてください（7-2）。 ログアウトはその画面のボタンからできます
ログインできるが一部の操作だけ拒否される app_metadata.role が staff チャンネル紐付け・Embedding 再生成・緊急停止は admin のみ。 role を admin にして再ログイン
ロールを付けたのに反映されないJWT が古いログアウト → 再ログイン（必須）
そもそもアカウントが作れないサインアップを無効化してある（正しい設定） Supabase → Authentication → Users → Add user で個別に作成する

別の生徒として回答されている

個人情報の観点で最も重大な不具合です。見つけたらすぐ緊急停止してください。

原因はチャンネル紐付けの登録ミス（チャンネル ID と生徒の対応が違う）です。 「誰の質問か」はチャンネル ID だけで決まるため、紐付けが間違っていれば他の生徒のプロフィールとレポートを使って回答してしまいます。

  1. AI 応答を緊急停止
  2. /admin/channels で、チャンネル ID と生徒の対応を全件確認する
  3. 誤っている紐付けは作り直す（チャンネル ID と生徒は編集できません。既存を無効化して新規登録）
  4. /admin/conversations で影響範囲（誤って参照された会話）を確認する
  5. 再開して、該当チャンネルで正しい生徒として応答することを確認する

環境変数を変えたのに反映されない

変数反映のされ方必要な操作
NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_ANON_KEY		 ビルド時にバンドルへ埋め込まれる 再デプロイ必須。「Use existing Build Cache」のチェックを外して Redeploy
それ以外すべて起動時に読まれる再デプロイ（新しい関数インスタンスが必要）

Vercel のダッシュボードで値を書き換えただけでは、動いている関数には反映されません。 必ず Deployments → 最新 → Redeploy を実行してください。

それでも解決しないとき

  1. Vercel の Runtime Logs を /api/slack/events で絞り込み、該当時刻の記録を探す
  2. /admin/errors を深刻度すべてにして、同じ時刻のログを探す
  3. /admin/jobs をすべてにして、該当ジョブの状態と試行回数を見る
  4. それでも不明なら、Slack のイベントが届いているかどうかで問題を二分する （届いていない = Slack 側の設定 / 届いている = アプリ側の判定）
