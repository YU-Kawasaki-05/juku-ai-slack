STEP 6 — Slack イベント購読の設定

STEP 4 で作った Slack アプリに、「メッセージが来たらこの URL に投げてね」を教えます。 アプリがデプロイ済みで SLACK_SIGNING_SECRET が入っている今、はじめてこの設定が保存できます。

所要時間約 10 分
前提STEP 5 完了（/login が表示される状態）
このステップで手に入るものSlack → アプリのイベント配信経路
（控える値はありません）

6-1. Request URL を登録する

  1. https://api.slack.com/apps → STEP 4 で作ったアプリを開く
  2. 左メニュー Event Subscriptions
  3. Enable Events を On にする
  4. Request URL に次を入力する
https://<あなたのドメイン>/api/slack/events

例: https://juku-ai-slack.vercel.app/api/slack/events （<あなたのドメイン> は STEP 5-4 で控えた Production のドメイン。プレビュー URL は使わない）

入力欄からフォーカスを外すと Slack が自動で検証し、数秒で ✓ Verified の緑色バッジが出れば成功です。

裏で何が起きているか

Slack はこの URL に {"type":"url_verification","challenge":"..."} という POST を投げ、 3 秒以内に challenge の値をそのまま返すことを要求します。 アプリ側は署名検証を先に通してから返しているため、 SLACK_SIGNING_SECRET が正しく設定されていないと 401 になり Verified になりません。

受信 → ① 署名検証（SLACK_SIGNING_SECRET）
       ② JSON パース
       ③ type === "url_verification" なら challenge を返す  ← ここ

根拠: src/app/api/slack/events/route.ts。署名が合わなければ return new NextResponse('invalid signature', { status: 401 }) で即座に返し、 検証を通った場合だけ NextResponse.json({ challenge }) を返します。

6-2. Verified にならないときの原因表

Slack の画面には Your URL didn't respond with the value of the challenge parameter のような そっけないメッセージしか出ません。原因は次のどれかです。上から順に確認してください。

#確認すること症状 / 見分け方対処
1 URL のパスが正しいか 末尾が /api/slack/events になっているか。/api/slack/event（s 抜け）や末尾スラッシュ付きは 404 正確に https://<ドメイン>/api/slack/events。ブラウザで開いて 405 か Method Not Allowed が返ればパスは正しい（GET は未実装なので 404 でなければ OK）
2 SLACK_SIGNING_SECRET が本番に入っているか 最頻出。Vercel の Runtime Logs に [slack/events] signature verification failed: が出ていれば確定 Vercel → Settings → Environment Variables を確認。Production にチェックが入っているか、 値の前後に空白・改行が混ざっていないか。修正後は再デプロイが必要
3 Signing Secret の値が Slack 側と一致しているか 同上のログが出るが、変数は設定済み Slack → Basic Information → App Credentials → Signing Secret を Show して再コピー。 Client Secret や Verification Token と取り違えていないか（別物です）
4 他の環境変数の形式エラーでアプリ全体が 500 になっていないか /login を開いても 500。Runtime Logs に Missing or invalid env vars: ... env は起動時に一括検証されるため、Slack と無関係な変数（例: RESEND_FROM_EMAIL の空文字）1 つで全滅します。 該当変数を修正するか行ごと削除（STEP 5-2）
5 デプロイが成功しているか Vercel の Deployments が Error 表示 直前のビルド失敗で古い版のまま、あるいは未デプロイ。ビルドログを確認して直す
6 Production ドメインを使っているか プレビュー URL（xxx-git-...vercel.app）を登録している プレビューには Vercel Authentication（SSO 保護）が掛かっていることがあり、 Slack のリクエストがログイン画面（HTML）にリダイレクトされて失敗する。Production ドメインに変更
7 Deployment Protection が有効になっていないか Production でも 401 の HTML が返る Vercel → Settings → Deployment Protection を確認。Production に保護を掛けている場合は解除する （Slack はヘッダを付けられません）
8 サーバー時刻のズレ 署名は合っているのに失敗が続く（極めて稀） 署名検証はタイムスタンプの許容ずれを 300 秒としています （SLACK_TIMESTAMP_TOLERANCE_SEC）。Vercel 側では通常起きません

ログの見方: Vercel → プロジェクト → Logs（または該当 Deployment の Runtime Logs）で /api/slack/events を絞り込みます。Slack の「Retry」ボタンを押すと再検証できるので、 ログを開いたまま試すと原因が特定しやすいです。

6-3. 購読するイベントを追加する

Verified になったら、同じ画面の Subscribe to bot events を開いて Add Bot User Event から追加します。

イベント入れるべきか理由
message.channels 必須 公開チャンネルのメッセージ。生徒チャンネルを公開で運用するなら必ず必要
message.groups 非公開なら必須 非公開チャンネルのメッセージ。STEP 1-3 で非公開を選んだ場合に追加
app_mention 不要 入れないでください。受信ハンドラは event.type !== 'message' を即座に捨てるため、 購読しても処理されません。メンション判定は message イベント本文に <@<Bot User ID>> が含まれるかを自前で見ています。 入れると同じ発言で 2 イベント届き、Slack の配信量が無駄に倍増します
message.im / message.mpim 不要 DM 運用はしません。紐付けは生徒専用チャンネル単位です
file_shared 不要 画像は message イベントの files 配列（subtype: file_share）から取得します

迷ったら message.channels と message.groups の両方を入れてください。 後から非公開チャンネルを足したくなったときの再設定が不要になります （対応する channels:history / groups:history スコープも両方入れておく）。

追加したら画面右下の Save Changes を必ず押します。

6-4. アプリを再インストールする

イベントやスコープを変更すると、画面上部に 「You've changed the permission scopes... please reinstall your app」 の黄色いバナーが出ます。再インストールしないと変更は反映されません。

  1. バナーの reinstall your app リンク、または左メニュー OAuth & Permissions → Reinstall to <ワークスペース名>
  2. 権限確認画面 → 許可する

Bot Token は変わるのか？ 同じワークスペースへの再インストールでは通常 xoxb- トークンは変わりません。 ただし念のため OAuth & Permissions の Bot User OAuth Token を確認し、 STEP 5 で設定した SLACK_BOT_TOKEN と一致しているかを見てください。 違っていたら Vercel の環境変数を更新して再デプロイします。

6-5. ここまでの確認

この時点ではまだ生徒チャンネルが無く、Bot も招待されていないので、質問しても反応しません。 確認できるのは「配線が通ったこと」までです。

簡易的な疎通テスト（任意）

適当な公開チャンネル（例 #general）に Bot を招待して @じゅくAI テスト と書くと、 紐付けが無いチャンネルなので次の案内が返ってくるはずです。

このチャンネルにはまだBotの設定が完了していないみたい。管理者に確認してもらえると助かります！

これが返れば Slack → Vercel → DB → Slack の往復が全部つながっています。 返らない場合は トラブルシューティング「Bot が反応しない」 を確認してください。

テストが済んだら、そのチャンネルから Bot を退出させておきます（/remove @じゅくAI または チャンネル詳細 → インテグレーション → アプリを削除）。紐付けの無いチャンネルにメンションが飛ぶたびに CHANNEL_NOT_BOUND の警告ログが積まれるためです。
