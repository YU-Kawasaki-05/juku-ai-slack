STEP 8 — 本番疎通確認

実際の Slack で動かして、生徒に渡せる状態かを確認します。ここを飛ばさないでください。 これまでのステップは「設定した」だけで、通しで動くかは別問題です。

所要時間約 20 分
前提STEP 7 完了（生徒 1 名 + チャンネル紐付け + Bot 招待済み）
用意するものテスト用の画像 1 枚
（数学の問題を撮った写真など。5MB 以下推奨）

テストは「生徒本人のチャンネル」で行います。生徒がすでに参加している場合、テストの発言が本人に見えます。 気になる場合は、先にテスト専用の生徒とチャンネルを作って確認し、終わったらその生徒を無効にしてください。

8-1. 基本の往復（メンション → 🤔 → 回答）

紐付け済みの生徒チャンネルで、Bot をメンションして質問します。

@じゅくAI 二次方程式の解の公式を教えて
#期待される動き目安時間
1送信したメッセージに 🤔（:thinking_face:）が付く1〜3 秒
2スレッドの返信としてAI の回答が投稿される5〜30 秒
3🤔 が外れる回答直後

ここが通れば、Slack → Vercel → DB → LLM → Slack の全経路が生きています。 このアプリで一番大きな関門です。

回答はチャンネル直下ではなくスレッドに付きます。これは仕様です （チャンネルを回答で埋めず、1 つの質問に 1 スレッドで会話を続けるため）。

反応が無い場合は トラブルシューティング「Bot が反応しない」へ。 🤔 は付くのに回答が来ない場合は 「🤔 のまま止まる」へ。

8-2. スレッド追撃（メンション不要）

いま返ってきた回答のスレッドの中で、メンションを付けずに続けて質問します。

もう少しやさしく説明して

メンション無しでも反応すれば正解です。一度 AI が答えたスレッドは会話セッションとして記録されており、 そのスレッド内の発言には（生徒が名指ししなくても）反応するようになっています。

逆に、チャンネル直下でメンション無しに発言しても Bot は反応しません。 これも仕様です（講師どうしの雑談に割り込まないため）。 テストとして、チャンネル直下に「テスト」とだけ書いて無反応であることも確認しておくと安心です。

会話が続いているかの確認

前の回答を踏まえた返答になっているか（「さっきの公式を使うと…」のように文脈を保っているか）を見てください。 文脈が切れている場合は、スレッドではなくチャンネル直下に書いていないか確認します。

8-3. 未紐付けチャンネルの案内

紐付けていないチャンネル（例 #general）に Bot を招待して、メンションします。

@じゅくAI テスト

次の定型文が返れば正常です。

このチャンネルにはまだBotの設定が完了していないみたい。管理者に確認してもらえると助かります！

確認が済んだらそのチャンネルから Bot を退出させてください （放置すると CHANNEL_NOT_BOUND の警告ログが溜まります）。

8-4. 画像付きの質問

生徒チャンネルで、画像を添付し、本文でメンションして質問します。

@じゅくAI この問題の解き方を教えて
（画像を添付）
確認すること期待
回答が画像の中身に触れているかここが本番。画像を読めていれば問題文の内容に沿った回答になる
回答が一般論に終始していないか「問題を教えてください」のような返しなら画像が読めていない
/admin/conversations での表示該当スレッドの「状態」に画像添付ありのアイコンが付く

画像が無視されているときの最有力原因は LLM_MODEL_COMPLEX です。 未設定だと LLM_MODEL_DEFAULT にフォールバックし、そのモデルが Vision 非対応だと エラーも出さずに画像だけ無視してテキストで回答します。 Vercel の Runtime Logs に 画像ありだが LLM_MODEL_COMPLEX 未設定 の警告が出ていないか確認してください。

制限の確認（任意）

制限値超えたとき
1 メッセージの枚数3 枚4 枚目以降は黙って捨てられる（通知なし）
1 枚のサイズ20MB画像のみの投稿なら「画像が少し大きすぎたみたい。…」と返る
1 メッセージの合計8MB同上
対応形式JPEG / PNG / WebP「そのファイル形式にはまだ対応してないんだ…」と返る

本文がある質問では、画像の失敗は生徒に伝えられません（テキストだけで回答してしまいます）。 画像だけを送った質問のときにのみ、上記のエラー文言が返ります。

8-5. 管理画面でコストと記録を確認する

利用状況（/admin/usage）

見るところ期待異常なら
質問数テストした回数ぶん増えている0 なら記録されていない。/admin/jobs を確認
コスト$0.00 より大きい下記の警告を参照
総トークン入力・出力とも 0 でない0 なら LLM が呼ばれていない
画像付き質問8-4 のぶんが 1 件以上0 なら画像が処理されていない
モデル別 利用回数設定したモデル名が並ぶ想定と違うモデル名なら env の設定ミス

質問数とトークンは増えているのに、コストが $0.00 のまま → MODEL_PRICING にモデル名が未登録です。

コストはプロバイダの請求額ではなく、アプリ内の単価表から計算しています。 src/shared/lib/constants.ts の MODEL_PRICING に無いモデル名を使うと、 トークン数は記録されるのに推定コストだけが 0 になります（エラーにはなりません）。

対処: STEP 1 の手順でモデル名と単価を追記 → 再デプロイ。 既に記録済みのログは 0 のままです（さかのぼって計算し直されません）。 モデルを切り替えたときも同じ落とし穴があるので、運用手順書に書いておいてください。

グラフが読みにくい場合は、各グラフの グラフ / 表 切替で数値の表に変えられます。 なお Embedding のコストは記録されません（LLM 呼び出しのみ記録対象）。実額はプロバイダのダッシュボードで確認してください。

エラーログ（/admin/errors）

既定では エラー・警告 だけが表示されます。何も無いのが理想です。

出ていたコード意味対応
CHANNEL_NOT_BOUND8-3 のテストぶん想定内。対応済みにする で閉じる
AI_RESPONSE_FAILEDLLM 呼び出しの失敗詳細ページの「内部エラー詳細」を見る。API キー・モデル名・残高を確認
SLACK_FILE_DOWNLOAD_FAILED画像のダウンロード失敗files:read スコープの付与漏れ、または再インストール漏れ
SLACK_POST_FAILEDSlack への投稿失敗chat:write の漏れ、または Bot がチャンネル未参加
THREAD_SUMMARY_FAILEDスレッド要約の失敗回答自体は届いている。続くようならモデル名を確認

深刻度フィルタを すべて にすると 情報 レベルも見えます （重複イベントや退塾生の沈黙など、正常動作の記録が含まれます）。

ジョブ（/admin/jobs）

KPI期待異常なら
待機中滞留なし残っている = 処理が始まっていない
処理中滞留なし残っている = 途中で止まった（関数のタイムアウトを疑う）
失敗滞留なし1 件でもあれば行を開いてエラーコードを確認

状態フィルタを 完了のみ にすると、テストしたぶんのジョブが 完了 で並んでいるはずです。 この画面を開くだけで滞留ジョブの自動回収も走ります。

会話ログ（/admin/conversations）

テストした会話がスレッド単位で並び、件数・画像の有無が記録されていることを確認します。 生徒名で絞り込めるので、引き渡し時に「ここで生徒の質問内容を確認できます」と説明してください。

8-6. 緊急停止のテスト

本番運用前に、止められることを確認しておきます（止め方を知らないまま運用を始めるのが一番危険です）。

  1. /admin 最上部の AI応答 カード → AI応答を停止
  2. 理由に 疎通確認のテスト と入力して 停止する
  3. Slack で質問 → 🤔 が付かず、次の定型文だけが返る:
いまメンテナンス中でお返事ができないんだ :bow: しばらく経ってからもう一度質問してね。
  1. #alerts を設定していれば、通知が届いていることを確認
  2. AI応答を再開 に戻し、再び質問して回答が返ることを確認

再開を忘れないでください。停止したまま引き渡すと、全生徒が「メンテナンス中」の返答しか受け取れません。 ダッシュボードのカードが 稼働中（緑）になっていることを最後に必ず確認します。

8-7. 詳細な確認項目

ここで扱ったのは最低限の疎通です。レート制限・退塾生の沈黙・ジョブ再実行の二重返信ガードなど、 本番でしか確認できない項目を網羅したチェックリストを別途用意しています。
