STEP 5 — Vercel デプロイ

プランの確認: Hobby プランでは Serverless Function の最大実行時間がプラン上限に切り詰められます。 /api/slack/events は maxDuration = 300（5 分）を宣言しており、LLM 生成が長引いたときに これが必要です。切り詰められると 🤔 が付いたまま回答が返らず、ジョブが processing のまま残ります。 Pro プランを推奨します（STEP 1-4）。

5-2. 環境変数を設定する

Import 画面の Environment Variables（またはデプロイ後の Project Settings → Environment Variables）で設定します。 Environment は最低限 Production にチェック。Preview デプロイも使うなら Preview にも入れてください。

最重要の落とし穴: 使わない変数は「空文字で登録」せず、行ごと作らないでください。

環境変数は起動時に Zod で一括検証しています。*_BASE_URL や NEXT_PUBLIC_SUPABASE_URL は URL 形式、RESEND_FROM_EMAIL はメール形式でないと検証に失敗し、 Missing or invalid env vars: ... を投げてアプリ全体（Slack Webhook 含む）が 500 になります。 「任意」の変数でも、空文字で存在している状態は「未設定」ではなく「不正な値」として扱われます。

必須（6 個）— これが無いとアプリが起動しない

変数名値の取得元例注意
NEXT_PUBLIC_SUPABASE_URL Supabase → Settings → API → Project URL（STEP 2-2） https://abcdefghijkl.supabase.co URL 形式必須。末尾スラッシュを付けない。ビルド時にブラウザ側へ埋め込まれるので、変更したら再デプロイが必要
NEXT_PUBLIC_SUPABASE_ANON_KEY 同上 → anon / public eyJhbGciOiJIUzI1NiIs... ビルド時埋め込み。ブラウザから見えるのは設計どおり（ログイン・ログアウトにしか使わない）
SUPABASE_SERVICE_ROLE_KEY 同上 → service_role eyJhbGciOiJIUzI1NiIs... Sensitive 推奨 RLS を完全バイパス。絶対に NEXT_PUBLIC_ を付けない
SLACK_BOT_TOKEN STEP 4-4 xoxb-1234567890-... Sensitive 推奨 前後の空白に注意
SLACK_SIGNING_SECRET STEP 4-5 a1b2c3d4e5f6...（32 桁） Sensitive 推奨 未設定だと /api/slack/events が 500 になり、STEP 6 で Verified になりません
SLACK_BOT_USER_ID STEP 4-6（auth.test の user_id） U01ABCDEFGH U 始まり。B 始まりの Bot ID を入れると Bot が永久に無反応

AI 回答に必要（4 個）— 未設定だと Bot は反応するが回答できない

変数名値の取得元例注意
LLM_API_KEY 選んだ LLM プロバイダの管理画面 sk-... / sk-or-v1-... Sensitive 推奨 未設定だと AI_RESPONSE_FAILED
LLM_BASE_URL STEP 1-1 の表 https://api.openai.com/v1 URL 形式必須。OpenAI は /v1 まで、DeepSeek は https://api.deepseek.com
LLM_MODEL_DEFAULT STEP 1-1 gpt-4o-mini 未設定だと ConfigurationError。リトライしても直らない失敗になる。MODEL_PRICING に登録済みか確認
LLM_MODEL_COMPLEX STEP 1-1 gpt-4o 画像対応するなら必須 画像付き質問だけこちらを使う。未設定だと LLM_MODEL_DEFAULT にフォールバックし、Vision 非対応なら画像が黙って無視される

RAG（レポート参照）に必要（3 個）

変数名値の取得元例注意
EMBEDDING_API_KEY Embedding プロバイダの管理画面 sk-... Sensitive 推奨 LLM と同じキーでも別キーでもよい
EMBEDDING_BASE_URL STEP 1-2 https://api.openai.com/v1 URL 形式必須
EMBEDDING_MODEL STEP 1-2 text-embedding-3-small 1536 次元のモデルのみ。違う次元だと保存時に embedding dimension mismatch

3 つとも未設定なら RAG は静かに無効化されます（EmbeddingNotConfiguredError、severity=info、エラーログに残らない）。 1 つでも欠けると同じく無効になるので、設定するなら 3 つセットで入れてください。

任意（3 個）

変数名値の取得元例未設定時の挙動
SLACK_WORKSPACE_URL STEP 4-6（auth.test の url） https://your-juku.slack.com 管理画面のエラー詳細・ジョブ一覧の「Slack で開く」リンクが出ず、ID 表示にフォールバックする。URL 形式必須
SLACK_ALERTS_CHANNEL_ID STEP 7 で作る運用チャンネル（例 #jukuai-alerts）の ID C01ABCDEFGH AI 応答の停止・再開時の Slack 通知が飛ばない（停止・再開の操作自体は成功する）。設定する場合はそのチャンネルに Bot を招待しておくこと
ANTHROPIC_API_KEY — — 設定不要。Anthropic 直アダプタ用の予約変数だが、@anthropic-ai/sdk は依存から外してあるため現状は使えない。Claude を使うなら OpenRouter 経由（LLM_*）で

設定してはいけない / 不要（3 個）

変数名扱い理由
SLACK_API_BASE_URL 本番では設定しない 受け入れテストでモックサーバーへ向けるための差し替え口。ループバック（localhost / 127.0.0.1 / ::1）以外を指定しても無視されるが、本番に置く理由がない
RESEND_API_KEY 不要 コード上の利用箇所はゼロ。将来の保護者メール通知（FR-08）用の予約。設定しなくても全機能が動く
RESEND_FROM_EMAIL 不要 同上。設定するならメール形式必須（不正な値だとアプリ全体が 500 になる）

変数は全部で 19 個（必須 6 / AI 4 / RAG 3 / 任意 3 / 不要 3）。 一般的な構成では 13 個（必須 6 + AI 4 + RAG 3）を設定し、必要に応じて SLACK_WORKSPACE_URL と SLACK_ALERTS_CHANNEL_ID を足して 15 個になります。

NEXT_PUBLIC_ の扱い（重要）

NEXT_PUBLIC_ で始まる 2 つは ビルド時にバンドルへ埋め込まれます。 Vercel のダッシュボードで値を書き換えても、再デプロイしない限り反映されません （「値は変えたのにログインできない」の典型原因）。 変更したら Deployments → 最新 → Redeploy を実行してください。 なお Use existing Build Cache のチェックは外した方が確実です。

参考: .env.example との対応

リポジトリの .env.example がローカル開発用の雛形です。ローカルで動かす場合は cp .env.example .env.local して同じ値を入れます（.env.local は .gitignore 済み）。

ビルドが失敗したら原因対処

5-4. 本番ドメインを控える

デプロイ完了画面、または Project → Domains に表示される https://<プロジェクト名>.vercel.app が本番ドメインです。控えてください。

Slack の Request URL には、必ずこの「本番（Production）ドメイン」を使ってください。 デプロイごとに変わるプレビュー URL（xxx-git-branch-team.vercel.app）を登録すると、次のデプロイで壊れます。 独自ドメインを当てる予定があるなら、先に設定してからその URL を使う方が手戻りがありません。

5-5. 動作確認: /login が表示されるか

  1. ブラウザで https://<あなたのドメイン>/login を開く
  2. 「メールアドレス」「パスワード」の入力欄があるログイン画面が出れば OK
  3. https://<あなたのドメイン>/ を開くと /admin にリダイレクト → 未ログインなので /login に飛ばされる、という挙動も確認

ログイン画面にサインアップのリンクが無いことも確認してください。このアプリにサインアップ UI は存在しません （管理ユーザーは Supabase ダッシュボードから作ります → STEP 7）。

この時点でログインはまだできません

Auth ユーザーをまだ作っていないためです。STEP 7 で作成します。ここでは画面が出ることだけ確認できれば十分です。
