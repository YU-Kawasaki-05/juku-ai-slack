STEP 7 — 管理ユーザーと生徒の登録

ここから実データを入れていきます。「管理画面に入れるようにする」→「生徒を作る」→「Slack チャンネルと結びつける」の順です。 生徒 1 人ぶんを通しでやってみて、うまくいったら残りを流し込むのが安全です。

所要時間約 30 分（生徒 1 人ぶん。2 人目以降は 5 分程度）
前提STEP 6 完了（Request URL が Verified）
このステップで手に入るもの（控える）
  • 管理画面のログイン情報（メール / パスワード）
  • 生徒チャンネルの ID（C...）
  • （任意）#alerts チャンネルの ID

7-1. 管理ユーザーを Supabase で作成する

STEP 2-3 でサインアップを無効化したので、ユーザーはダッシュボードから手動で作ります。

  1. Supabase → Authentication → Users → Add user → Create new user
  2. 入力:
項目値
Email塾の担当者のメールアドレス（例 owner@example.com）
Password強固なものを生成して控える。初回ログイン後に本人に変更してもらう
Auto Confirm User必ずチェックを入れる
入れないとメール確認が終わるまでログインできません。このアプリには確認メールの再送 UI がありません

スタッフが複数いる場合は、この時点で全員ぶん作っておくと後が楽です。

7-2. 【必須】ロールを付与する

ユーザーを作っただけでは管理画面を開けません。 app_metadata.role に admin か staff を必ず設定してください。 ロールが無いアカウントはログインには成功しますが、生徒情報などは一切表示されず /admin/no-access（「このアカウントには管理画面の利用権限が設定されていません」）に案内されます。

user_metadata ではありません — そちらはログイン中の本人が書き換えられるため、権限判定に使うと権限昇格の穴になります。

Supabase → SQL Editor で実行します（メールアドレスは対象ユーザーのものに置き換え）。

-- 管理者
update auth.users
set raw_app_meta_data = raw_app_meta_data || '{"role":"admin"}'::jsonb
where email = 'owner@example.com';

-- スタッフ（管理者以外の運用担当）
update auth.users
set raw_app_meta_data = raw_app_meta_data || '{"role":"staff"}'::jsonb
where email = 'staff@example.com';

admin と staff の違い

操作staffadmin備考
管理画面へのログイン、一覧・詳細の閲覧○○
生徒の登録・編集、AI プロフィール編集○○
レポートの作成・編集・承認○○
エラーの対応済み切替・メモ記入○○
ジョブのスイープ・再実行○○
チャンネル紐付けの登録・編集×○channel_id は「誰の質問か」を決める信頼の基点なので管理者限定
Embedding の手動再生成×○API 課金が発生するため
AI 応答の緊急停止・再開×○カードの閲覧はできるが操作は拒否される

セットアップ作業をするあなた自身は必ず admin にしてください。 このあとの 7-8（チャンネル紐付け）が staff では実行できず、 この操作は管理者のみ実行できます で弾かれます。

反映には再ログインが必要

ロールは JWT に埋め込まれるため、付与前に発行されたセッションには反映されません。 対象ユーザーは一度ログアウト → 再ログインしてください。

確認

select email, raw_app_meta_data -> 'role' as role
from auth.users
order by created_at;

"admin" / "staff" が入っていれば OK です。

7-3. 管理画面にログインする

  1. https://<あなたのドメイン>/login を開く
  2. 7-1 のメールとパスワードでログイン
  3. /admin のダッシュボードが表示されれば成功

「このアカウントには管理画面の利用権限が設定されていません」と出たら、 7-2 のロール付与が漏れているか、付与前のセッションのままです。 その画面のログアウトボタンから抜けて、ロールを付与してから再ログインしてください。

出たメッセージ意味対処
メールアドレスまたはパスワードが正しくありません。認証情報の誤り、または Auto Confirm User 未チェックでメール未確認Supabase → Authentication → Users で該当ユーザーの Confirmed 状態を確認。パスワードは Reset password で再設定できる
ログイン処理でエラーが発生しました。時間をおいて再度お試しください。ネットワーク・レート制限・サーバー側エラー少し待って再試行。続くなら Vercel の Runtime Logs を確認
ログイン画面に戻され続けるCookie が保存できていないURL が https:// か、ブラウザが Cookie をブロックしていないか確認

ダッシュボード最上部に AI応答 / 稼働中 のカードが見えていれば、DB の kill_switches も正しく読めています。

7-4. 生徒を登録する

左メニュー 生徒管理 → 新規生徒。

項目必須入れ方
名前必須本名（例 山田 太郎）。100 文字まで。管理画面の一覧や集計に出る
表示名（任意）任意Bot が呼びかけに使う名前（例 太郎くん）。未設定なら名前が使われる
学年（任意）任意例 中学3年。AI の回答レベル調整の材料になる
ステータス必須有効のまま。無効にすると Bot が完全に沈黙し、集計や選択肢からも外れる（退塾時に使う → STEP 9）
保護者メール（任意）任意現時点でメール送信機能は未実装。記録用

保存 を押すと一覧に戻ります。

「保存」の二度押しに注意。生徒テーブルには重複を防ぐ一意制約がないため、 連打すると同姓同名の生徒が 2 件できます。保存後はボタンが自動で無効化されますが、 一覧に戻ったら 1 件だけになっているか確認してください。

7-5. AI 用プロフィールを入力する

登録した生徒の名前をクリック → 詳細ページの下半分に AI 用プロフィール カードがあります。 ここに書いた内容はその生徒の全質問の回答に毎回使われます（他の生徒には使われません）。

項目上限何を書くか
全体要約2000 字 現在の学習状況と直近の重点課題。200〜800 字が目安。
例:「中学3年。数学は基礎計算は安定してきたが、文章題で条件を式に落とすところでつまずきやすい。」
学習スタイル・説明トーン500 字 どう説明すると入りやすいか。
例:「図を使った説明が入りやすい。長文の説明は読み飛ばしがち。」
得意分野500 字例:「計算問題、暗記系」
苦手分野500 字例:「文章題、証明」
指導上の注意1000 字 やってほしくない教え方。
例:「答えをすぐ出すと写して終わりになりやすいので、まず考え方から。」

全部埋めなくても動きます（すべて任意項目）。ただし空だと「どの生徒にも同じ回答」になり、 このアプリの一番の価値である個別化が効きません。最低でも「全体要約」だけは書いてください。

試験期間の設定

同じカードの下部に 試験期間 があります。

項目説明
試験期間中にするチェックすると試験モードになる
最終日今日以降の日付。その日いっぱい（日本時間 24:00）まで試験期間として扱われ、過ぎると自動で通常に戻る
試験科目（任意）カンマ区切り（例 数学, 英語）。20 件まで、1 件 50 字まで

試験期間中は AI の答え方が変わります。 通常は理解度に応じて確認の質問を挟むことがありますが、試験期間中は 確認質問をはさまず、要点と解き方の例をすばやく提示するモード（direct）に固定されます。 試験直前に「まず自分で考えてみよう」と返されると困る、という現場の要求への対応です。 設定した科目名も AI に伝わります。

プロフィールを保存 を押すと、ボタンの横に 保存しました と出ます（ページは移動しません）。 生徒一覧では試験期間中の生徒に 試験期間中 のバッジが付きます。

7-6. Slack に生徒チャンネルを作り、Bot を招待する

チャンネルを作る

  1. Slack で + → チャンネルを作成
  2. 名前は分かりやすく（例 study-taro / 質問-山田太郎）
  3. STEP 1-3 で決めた方針どおり公開／非公開を選ぶ
  4. 生徒本人を招待する（保護者や担当講師も必要に応じて）

Bot を招待する（必須）

これを忘れると Bot は永久に無反応です。Slack はアプリが参加していないチャンネルのメッセージイベントを配信しません。 エラーログにも何も残らないため（そもそもイベントが届かない）、原因究明が一番やっかいなミスです。

チャンネルで次を実行します。

/invite @じゅくAI

「じゅくAI がチャンネルに参加しました」と表示されれば OK です。 チャンネル詳細 → インテグレーション タブにアプリが並んでいることでも確認できます。

生徒を追加するたびにチャンネル作成 → 招待がセットで必要です。運用手順書に必ず書いておいてください。

7-7. チャンネル ID とワークスペース ID を調べる

チャンネル「名」ではなく「ID」が必要です。チャンネル名は後から変更できてしまうため、 このアプリは channel_id（変わらない値）を「誰の質問か」の判定に使っています。 管理画面に入力するチャンネル名は一覧での表示用にすぎません。

チャンネル ID（C で始まる）

  1. Slack でチャンネル名をクリック → チャンネル詳細を開く
  2. ダイアログを一番下までスクロール
  3. チャンネル ID: C01ABCDEFGH と表示されている → コピーボタンで取得

ブラウザ版 Slack なら URL の末尾（.../messages/C01ABCDEFGH）でも確認できます。 非公開チャンネルでは G で始まることもありますが、どちらも登録できます。

ワークスペース ID（T で始まる）

STEP 4-6 の auth.test で取得した team_id です。 ワークスペース内で共通なので、生徒ごとに調べ直す必要はありません。

ブラウザ版 Slack の URL https://app.slack.com/client/T01ABCDEFGH/C01... の最初の ID でも確認できます。

7-8. チャンネルと生徒を紐付ける

管理画面 → チャンネル設定 → 新規チャンネル紐付け。この操作は admin のみです。

項目必須入れる値形式チェック
SlackチャンネルID必須7-7 で調べた C01ABCDEFGH C / G / D で始まり、以降は大文字英数字のみ。 小文字が混ざると チャンネルIDの形式が正しくありません（例: C01ABCDEFGH）
ワークスペースID必須T01ABCDEFGH T で始まり以降は大文字英数字。誤ると ワークスペースIDの形式が正しくありません（例: T01ABCDEFGH）
チャンネル名（任意）任意study-taro（# は不要）200 字まで。表示用のみ
生徒必須7-4 で作った生徒を選ぶ有効な生徒のみが選択肢に出る
既定レポート（任意）任意まだレポートが無いので 指定しない のままで OK 生徒を選ぶまで操作できない。承認済み・送信済みのレポートだけが候補

紐付ける を押して チャンネルを紐付けました が出れば完了です。

出たエラー意味対処
この操作は管理者のみ実行できますログイン中のユーザーが staff7-2 で admin を付与 → 再ログイン
このチャンネルはすでに紐付けされています同じチャンネル ID の登録が既にある一覧から既存の紐付けを開いて内容を確認・修正する（1 チャンネル = 1 生徒）
チャンネルIDの形式が正しくありません小文字混じり・# 付き・チャンネル名を入れている7-7 の手順で ID を取り直す

あとから変更できるのは「チャンネル名」と「ステータス」だけです。 チャンネル ID と生徒の対応を間違えた場合は、紐付けを作り直してください （間違ったまま運用すると、別の生徒のプロフィールとレポートを使って回答してしまいます）。

7-9. レポートを登録して Embedding を確認する

レポートは「AI に読ませる生徒ごとの学習記録」です。登録すると保存時に自動でベクトル化され、 以降の回答で参照されるようになります。

登録する

  1. 管理画面 → レポート → 新規レポート
  2. 入力:
項目内容
生徒対象の生徒（あとから変更できません）
対象月例 2026-08。同じ生徒 × 同じ月は 1 件のみ
タイトル例 2026年8月 学習レポート
AI 参照対象にするチェックしたまま（外すと Bot が参照しません）
本文（Markdown）単元の進捗・つまずき・宿題の状況など。編集／プレビューで表示を切り替えられます

Bot が参照するのは「承認済み」または「送信済み」のレポートだけです。 下書きのままでは RAG 検索の対象になりません。動作確認をするなら 承認して保存（左のボタン）を押してください。下書き保存は右のボタンです。

Embedding が生成されたか確認する

保存後、レポートの詳細ページを開いて次を確認します。

見るところ正常異常
ページ上部の警告バナー 出ていない Embedding 再生成が必要です が出ている
最終 Embedding の欄 保存した日時が入っている 未生成 のまま
保存直後のトースト レポートを保存しました 保存しました（AI 参照データは未更新）

異常だった場合、原因はほぼ EMBEDDING_* の設定です。

  • 3 つ（EMBEDDING_API_KEY / EMBEDDING_BASE_URL / EMBEDDING_MODEL）がすべて設定されているか。1 つでも欠けると無効になります
  • モデルが 1536 次元か（text-embedding-3-large は 3072 次元なので不可）
  • API キーの残高・利用制限

直したら再デプロイし、詳細ページの Embedding 再生成（管理者のみ）で作り直してください。 確認ダイアログに「API 利用コストが発生します」と出ますが、レポート 1 件ぶんなので微小です。

レポートが無くても Bot は動きます（プロフィールと会話履歴だけで回答します）。 疎通確認を優先するなら、レポートは後回しでも構いません。

7-10. 【任意】#alerts チャンネルを用意する

AI 応答を緊急停止・再開したときに Slack へ通知を飛ばしたい場合に設定します。

  1. Slack で運用者向けチャンネルを作る（例 #jukuai-alerts）。生徒は入れない
  2. /invite @じゅくAI で Bot を招待する（招待しないと投稿できません）
  3. 7-7 の手順でチャンネル ID を取得
  4. Vercel → Settings → Environment Variables に SLACK_ALERTS_CHANNEL_ID を追加 → 再デプロイ

未設定でも停止・再開の操作自体は成功します（通知が飛ばないだけで、 トーストに AI応答を停止しました（#alerts への通知はできませんでした） と出ます）。
