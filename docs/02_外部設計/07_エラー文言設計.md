# エラー文言設計 — juku-ai-slack-bot

## 設計方針

- 中高生が読む文言。難しい技術用語を使わない
- 「申し訳ありません」の謝罪より「もう一度試してね」の行動提示を優先
- ユーザーが何をすれば解決するかを具体的に書く
- エラーの詳細（スタックトレース・エラーコード）は絶対に出力しない
- severity=info のエラーはSlackへの通知なし

> 「管理者への通知」は **`/admin/errors` に severity=error として並び、日次確認の対象になる**という意味。
> Slack へ自動アラートが飛ぶのは kill_switch の状態変化のみ（DEC-15。`docs/03_技術設計/06_運用設計.md` 2.1）。

### 補足: 意図的な打ち切り（severity=info）の 3 コード

`AI_PAUSED` / `RATE_LIMITED` / `PERSON_INACTIVE` は障害ではなく**設計どおりの打ち切り**。
いずれも LLM を呼ぶ前に判定し、ジョブは `failed` ではなく `completed` で閉じてリトライしない。

| コード | 判定箇所 | ジョブの終わり方 |
|-------|---------|----------------|
| AI_PAUSED | `processJob`（claim 直後・🤔 付与の前）。`isAIEnabled()` が false | `completed` + `error_code='AI_PAUSED'` |
| RATE_LIMITED | `executeProcessMessage`（画像DL・RAG・LLM より前）。直近1時間 10 件超（`RATE_LIMIT_QUESTIONS_PER_HOUR`） | `completed`（正常終了扱い） |
| PERSON_INACTIVE | `/api/slack/events`（ジョブ登録より前）。`persons.status='inactive'` | ジョブを作らない。receipt を `skipped` にする |

`JOB_TIMEOUT` は `sweepStaleJobs()`（`/admin/jobs` のスイープ）だけが記録する。
`USER_FACING_MESSAGES` に文言は用意してあるが、**スイーパからは Slack に投稿しない**
（kill される直前に回答済みの可能性があり、詫び文言を送ると二重返信になるため）。
生徒への再通知が要るときは `/admin/jobs` の「再実行」を使う。

### 補足: 操作ログとしての 2 コード（CHANNEL_BINDING_CREATED / UPDATED）

この 2 つは**エラーではなく操作の記録**。`ai_error_logs` を操作ログ置き場としても使っている
（専用テーブルは作らない）。チャンネル紐付けを誤ると**別生徒のプロフィールとレポートで AI が
回答する**ため、EP-07〜09 を staff に開放した代わりに「誰がいつどの紐付けをしたか」を必ず残す
（`03_権限設計.md` 3.1）。

| 項目 | 内容 |
|------|------|
| 記録箇所 | `createBindingAction` / `updateBindingAction`（`src/features/channel-bindings/actions/`） |
| severity | `info`（Slack 返信なし・管理者通知なし。`/admin/errors` に並ぶだけ） |
| 生徒への露出 | なし。`USER_FACING_MESSAGES` には登録しない（Slack の返信経路を通らない） |
| `slack_channel_id` | 対象チャンネル |
| `person_id` | 紐付け先の生徒 |
| `internal_message` | `key=value` の並び（後から grep するため形式を固定。未設定値は `-`） |
| 重複除去 | **使わない**。`dedupeWhileUnresolved` を付けると 2 件目以降が消え、操作ログとして機能しない |

`internal_message` に入れる key:

- 作成: `actor`（操作者のメールアドレス）/ `channel_id` / `channel_name` / `person_id` /
  `person_name` / `default_report_id` / `status`
- 更新: `actor` / `binding_id` / `channel_id` / `channel_name` /
  `person_id_before` / `person_id_after` / `status_before` / `status_after`

更新時に `person_id_before` と `person_id_after` を両方残すのは、**付け替わっていないこと自体**を
後から検証できるようにするため（`person_id` は UI から変更できない = BR-15-01。両者が食い違う
ログが出たらそれが事故の証拠になる）。

## Slack返信文言（確定版）

### CHANNEL_NOT_BOUND
> このチャンネルにはまだBotの設定が完了していないみたい。管理者に確認してもらえると助かります！

### PERSON_NOT_FOUND
> 対応する生徒情報が見つからなかったよ。管理者に確認してもらうね。

### SLACK_FILE_DOWNLOAD_FAILED
> 画像の取得に失敗しちゃった :sweat_smile: 少し時間を置いてもう一度送ってみてね。

### UNSUPPORTED_FILE_TYPE
> ごめん、そのファイル形式にはまだ対応してないんだ。画像（jpg / png）で送ってもらえる？

### IMAGE_TOO_LARGE
> 画像が少し大きすぎたみたい。圧縮してもう一度送ってみてね！

### IMAGE_PROCESSING_FAILED
> 画像の処理がうまくいかなかったけど、テキストの内容で回答するね。

### 読めなかった画像の案内（回答末尾に添える1行）

定型文を単独送信するのではなく、**AI 回答本文の末尾**に足す（`buildImageNotice()`）。
回答を止めないこと・1ジョブ1配信（A-3）を崩さないこと・会話ログに証跡を残すことが目的。

- 一部/全部が読み込めなかったとき
  > （送ってくれた画像のうち N 枚は読み込めなかったんだ。文章の内容から答えたよ。もう一度送るときは jpg / png で、サイズを小さめにしてみてね）
- Vision 対応モデル未設定のとき（`IMAGE_MODEL_NOT_CONFIGURED`）
  > （ごめん、いまは画像を読み取れないみたい。文章の内容から答えたよ。図や式が大事なときは文章でも教えてくれると助かる！）

N には「DL/形式/サイズ失敗」に加え、**受信時に枚数上限（`MAX_IMAGES_PER_MESSAGE`）で捨てた分**と
**合計サイズ上限（`MAX_TOTAL_IMAGE_BYTES`）でスキップした分**も含める（無通知の破棄を作らない）。
Vision 未設定時は枚数の内訳を出さない（生徒が取れる行動が変わらないため 1 行に丸める）。

### IMAGE_MODEL_NOT_CONFIGURED（運用者向け）

`LLM_MODEL_COMPLEX` 未設定のまま画像付き質問が来ると、`LLM_MODEL_DEFAULT` にフォールバックし
**画像は事実上無視される**。原因が画面から分かるよう `ai_error_logs` に warning で記録する。
設定を直すまで再発し続けるため、`logError(..., { dedupeWhileUnresolved: true })` により
**未解決の同一コードが 1 件ある間は追加記録しない**（B-8 と同じログ洪水対策）。
解決済みにしても直っていなければ次の発生で再び 1 件積まれる。

### AI_RATE_LIMITED
> いま少し混み合ってるみたいで、すぐ答えられないや :sweat: 1〜2分後にもう一度送ってみてね！

### AI_TIMEOUT
> 回答の生成に時間がかかりすぎてしまった。質問を少し短くしてもう一度送ってみてね。

### AI_RESPONSE_FAILED
> うまく処理できなかったみたい :sweat_smile: もう一度試してみて。続くようなら先生に教えてね。

### TOKEN_BUDGET_EXCEEDED
> 質問が少し長すぎて処理できなかったよ。短くして送ってみてね！

### JOB_TIMEOUT（定義済みだが現状は未送信。上記の補足を参照）
> 処理がタイムアウトしちゃった。もう一度質問を送ってみてね！

### AI_PAUSED
> いまメンテナンス中でお返事ができないんだ :bow: しばらく経ってからもう一度質問してね。

### RATE_LIMITED
> 今日はたくさん質問してくれてありがとう！ちょっと休憩して、1時間ほどしてからまた質問してね :relaxed:

### UNKNOWN_ERROR
> うまく処理できなかったみたい :sweat_smile: もう一度試してみて。続くようなら先生に教えてね。
