## なぜ手動確認が要るのか

自動テスト 86 件はすべて **モック Slack + モック LLM** に対して走っている（詳細 → `20_slackフロー.md`）。
つまり以下は**一度も検証されていない**。

- 実 Slack の **3 秒 ACK 制約**（超えると Slack がイベントを再送する）
- Vercel の**コールドスタート**と `maxDuration=300` 下での実応答時間
- 実 LLM の**応答品質・レイテンシ・実トークン単価**
- Slack **スコープ**（`chat:write` / `reactions:write` / `channels:history` / `files:read`）の充足
- **画像添付**（`files.download` + Vision モデル）
- `#alerts` チャンネルへの**実着弾**

**ここを飛ばして引き渡すと、初日に全部が同時に発覚する。**

## AT-P01 基本の往復（メンション → 🤔 → 回答 → 🤔 除去）【必須】

**手順**: 紐付け済みの生徒チャンネルで `@じゅくAI 二次方程式の解の公式を教えて` と送信。

| # | 期待結果 | 目安 | 確認 |
|---|---|---|---|
| 1 | 送信したメッセージに 🤔（`:thinking_face:`）が付く | 1〜3 秒 | [ ] |
| 2 | **スレッドの返信として** AI の回答が投稿される（チャンネル直下ではない） | 5〜30 秒 | [ ] |
| 3 | 🤔 が外れる | 回答直後 | [ ] |
| 4 | 回答内容が質問に答えている（一般論に逃げていない） | — | [ ] |

**実測値を記録**: 🤔 まで ______ 秒 / 回答まで ______ 秒

- [ ] 同じ質問を**もう一度**投げて、2 回目（ウォーム状態）の応答時間も記録: ______ 秒

> ここが通れば Slack → Vercel → DB → LLM → Slack の全経路が生きている。**一番大きな関門。**
> 反応が無い → トラブルシューティング「Bot が反応しない」。
> 🤔 は付くのに回答が来ない → 「🤔 のまま止まる」。

## AT-P10 応答時間とコールドスタート【必須】

**手順**: AT-P01 の実測値と Vercel の Runtime Logs を突き合わせる。

| # | 期待結果 | 確認 |
|---|---|---|
| 1 | 初回（コールド）でも回答が届く。無言で消えない | [ ] |
| 2 | Vercel Runtime Logs に関数タイムアウト（`Task timed out` 等）が**無い** | [ ] |
| 3 | 同じイベントが Slack から**再送されていない**（回答が 2 通来ていない） | [ ] |
| 4 | `/admin/jobs` を開き、テストしたジョブが **完了** になっている | [ ] |

> #3 が起きる場合、ACK が 3 秒に間に合っていない可能性が高い。
> ACK 自体は `after()` の前に返しているので通常は起きないが、コールドスタートが極端に遅いと発生しうる。
> 発生した場合は `ai_error_logs` に `SLACK_EVENT_DUPLICATE` が残っているはず（= 二重返信は防げている）。

## AT-P02 スレッド追撃（メンション不要）で文脈が続く【必須】

**手順**: いま返ってきた**回答のスレッドの中**で、メンションを付けずに `もう少しやさしく説明して` と送信。

| # | 期待結果 | 確認 |
|---|---|---|
| 1 | メンション無しでも反応する | [ ] |
| 2 | **前の回答を踏まえた返答**になっている（「さっきの公式を使うと…」のように文脈を保つ） | [ ] |

> #2 は自動テストでは検証できない（モック LLM は履歴を無視して固定文を返すため）。

## AT-P05 画像添付の質問【必須】

**手順**: 生徒チャンネルで、画像を添付し**本文でメンションして** `@じゅくAI この問題の解き方を教えて` と送信。

| # | 期待結果 | 確認 |
|---|---|---|
| 1 | 回答が**画像の中身に触れている**（問題文の内容に沿っている） | [ ] |
| 2 | 「問題を教えてください」のような一般論に終始していない | [ ] |
| 3 | `/admin/conversations` の該当スレッドに「画像添付あり」のアイコンが付く | [ ] |
| 4 | `/admin/errors` に `SLACK_FILE_DOWNLOAD_FAILED` が**無い** | [ ] |

> 画像の中身に触れずテキストだけの回答が返るときの最有力原因は **`LLM_MODEL_COMPLEX` 未設定**。
> 未設定だと画像は LLM に送らず**テキストのみで回答**し、生徒には「画像は読み取れなかった」旨を添える
> （回答が返らないわけではない）。運用者向けには `IMAGE_MODEL_NOT_CONFIGURED` がエラーログに残るので、
> `/admin/errors` または Vercel Runtime Logs にこれが出ていないか確認する。

## AT-P06 画像の制限挙動【推奨】

| 制限 | 値 | 超えたときの挙動 | 確認 |
|---|---|---|---|
| 1 メッセージの枚数 | 3 枚 | 4 枚目以降は**黙って捨てられる**（通知なし） | [ ] |
| 1 枚のサイズ | 20MB | 画像のみの投稿なら「画像が少し大きすぎたみたい。…」 | [ ] |
| 1 メッセージの合計 | 8MB | 同上 | [ ] |
| 対応形式 | JPEG / PNG / WebP | 「そのファイル形式にはまだ対応してないんだ…」 | [ ] |

> **本文がある質問では、画像の失敗は生徒に伝えられない**（テキストだけで回答してしまう）。
> 上記のエラー文言が返るのは**画像だけを送った質問のとき**に限られる。

## AT-P07 実 LLM でのコスト記録【必須】

**手順**: `/admin/usage` を開く。

| # | 見るところ | 期待 | 確認 |
|---|---|---|---|
| 1 | 質問数 | テストした回数ぶん増えている（0 なら記録されていない → `/admin/jobs` へ） | [ ] |
| 2 | コスト | **`$0.00` より大きい** | [ ] |
| 3 | 総トークン | 入力・出力とも 0 でない（0 なら LLM が呼ばれていない） | [ ] |
| 4 | 画像付き質問 | AT-P05 のぶんが 1 件以上 | [ ] |
| 5 | モデル別 利用回数 | 設定したモデル名が並ぶ（想定と違うなら env の設定ミス） | [ ] |
| 6 | 「単価が未登録のモデル」警告 | **出ていない** | [ ] |

> **質問数とトークンは増えているのにコストが `$0.00` のまま** → `MODEL_PRICING` にモデル名が未登録。
> コストはプロバイダの請求額ではなく `src/shared/lib/constants.ts` の単価表から計算している。
> 対処: STEP 1 の手順でモデル名と単価を追記 → 再デプロイ。
> **既に記録済みのログは 0 のまま**（さかのぼって計算し直されない）。
> モデルを切り替えたときも同じ落とし穴があるので、運用手順書に書いておく。
>
> なお **Embedding のコストは記録されない**（LLM 呼び出しのみ記録対象）。実額はプロバイダのダッシュボードで確認する。

**記録**: 今月のコスト ______ / 総トークン（入力）______ /（出力）______

## AT-P09 + AT-P08 緊急停止と #alerts 通知【必須】

**止め方を知らないまま運用を始めるのが一番危険。** 引き渡し前に必ず一度止めて戻す。

**手順**:

| # | 操作・期待結果 | 確認 |
|---|---|---|
| 1 | `/admin` 最上部の AI応答カード →「AI応答を停止」→ 理由に `疎通確認のテスト` →「停止する」 | [ ] |
| 2 | カードが **停止中** になり、理由が表示される | [ ] |
| 3 | **`#alerts` に通知が届いている**（`SLACK_ALERTS_CHANNEL_ID` 設定時） | [ ] |
| 4 | 通知本文に「AI応答を停止しました」・入力した理由・**操作者のメールアドレス**が含まれる | [ ] |
| 5 | Slack で質問 → 🤔 が**付かず**、次の定型文だけが返る:<br>`いまメンテナンス中でお返事ができないんだ :bow: しばらく経ってからもう一度質問してね。` | [ ] |
| 6 | 「AI応答を再開」→ 理由入力 →「再開する」 | [ ] |
| 7 | `#alerts` に**再開の通知**も届く | [ ] |
| 8 | 再び質問して**回答が返る** | [ ] |
| 9 | ダッシュボードのカードが **稼働中**（緑） | [ ] |

> #3 が届かない場合の原因: `SLACK_ALERTS_CHANNEL_ID` の設定ミス / そのチャンネルに Bot が未招待 /
> `chat:write` スコープの漏れ。**自動テストは投稿先がモックのためこれらを検出できない。**
>
> **再開を忘れないこと。** 停止したまま引き渡すと全生徒が「メンテナンス中」の返答しか受け取れない。
