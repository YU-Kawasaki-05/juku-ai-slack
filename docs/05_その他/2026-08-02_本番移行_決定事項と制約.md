## 2. ⚠️ LLM は単一プロバイダに揃えなければならない（コード制約）

**`LLM_MODEL_DEFAULT` と `LLM_MODEL_COMPLEX` は base URL と API キーを共有する。**

```
src/features/ai-answer/lib/llm/getLlmClient.ts:23-28
  env.LLM_API_KEY + env.LLM_BASE_URL から「単一のクライアント」を生成しモジュールキャッシュする

src/features/jobs/lib/executeProcessMessage.ts:213
  const useModel = imageDataUrls.length > 0 ? (env.LLM_MODEL_COMPLEX ?? model) : model
  → 差し替えているのは「モデル名の文字列」だけ
```

したがって **プロバイダ A のテキストモデル + プロバイダ B の Vision モデル** という構成は現在の実装では組めない。

| 選択肢 | 内容 | 判断 |
|---|---|---|
| **単一プロバイダで両方揃える（OpenAI 直）** | `gpt-5.6-luna`（テキスト）と `gpt-5.6-terra`（画像）はどちらも OpenAI のモデルなので、base URL を共有しても成立する | **採用** |
| OpenRouter に一本化 | `LLM_BASE_URL=https://openrouter.ai/api/v1`、モデルは `provider/model` 形式 | **見送り**。理由は下記 |
| 画像対応を諦める | `LLM_MODEL_COMPLEX` 未設定 | **不可**。§6 のとおり未設定は「画像が無視される」ではなく「画像付き質問が失敗しうる」 |
| コード変更 | COMPLEX 用に別 baseURL / キーを持たせる | env・client・テストに波及。不要になったので見送り |

**Embedding は独立**（`EMBEDDING_BASE_URL` / `EMBEDDING_API_KEY` が別変数）なので、LLM と別プロバイダにもできる。
ただし OpenAI 直に揃えるなら**キー 1 本・請求 1 本**に統合できる。

### 2-1. OpenRouter を見送った理由

当初は「DeepSeek（安価なテキスト）＋ OpenAI（Vision）を混在させる」ために OpenRouter を前提にしていたが、
調査（→ `docs/05_その他/2026-08-02_OpenRouter導入要件.md`）の結果、**その前提が不要になった**。

| # | 理由 | 詳細 |
|---|---|---|
| 1 | **混在の必要が消えた** | `gpt-5.6-luna` が Vision 対応かつ安価（$0.20/$1.20）。**1 モデルで DEFAULT と COMPLEX を兼ねられる**ので、そもそも単一 baseURL 制約に当たらない |
| 2 | **コスト差が意思決定要因にならない** | 20 名規模では LLM 代が月 $1〜2 で、インフラ固定費 $20 が支配的。→ §4 |
| 3 | **プライバシーを守るのにコード変更が必要** | `provider.data_collection` の**既定が `"allow"`**（保存・学習しうるプロバイダを許可）。守るにはリクエストごとに `"deny"` を明示送信する必要があり、現行クライアントは `provider` を送っていない。加えて **DeepSeek 一次プロバイダは `training: true` / `retainsPrompts: true`**（80 プロバイダ中 `training: true` は DeepSeek と NVIDIA の 2 社のみ） |
| 4 | **ZDR 強制で可用性メリットが消える** | 画像用 GPT-5 系の提供元は OpenAI と Azure のみ。ZDR を強制すると Azure 1 社に固定される |
| 5 | **Azure 経路で `max_tokens` が黙って無視される** | Azure エンドポイントは `max_completion_tokens` のみ受け、非対応パラメータは**エラーにならず無視される**。出力上限が効かなくなり、400 も返らないので気づけない |
| 6 | **Organization を先に作る必要がある** | 個人アカウントは組織に変換できない。後から移すとキー再発行＋クレジット移管 |
| 7 | **障害点が増える** | OpenRouter 自身が経路に加わる。数値 SLA はない |
| 8 | **引き渡しの障害** | Pay-as-you-go では公開情報上、請求書払い・銀行振込に非対応（カード / AliPay / USDC）。塾に契約を移す前提では説明しにくい |

**再検討するとしたら**: DeepSeek v4 Flash の品質・速度が luna より明確に上だと実測で分かった場合のみ。
そのときは上記 3・5 のコード変更（`provider` オブジェクト送信、エンドポイント固定）が前提条件になる。
なお**モデル比較の検証フェーズで使うのは OpenRouter の本領**なので、比較目的の一時利用は妥当。

## 3. モデル選定

**`LLM_MODEL_DEFAULT` = `gpt-5.6-luna` / `LLM_MODEL_COMPLEX` = `gpt-5.6-terra`（OpenAI 直）。**

### 3-0. 確定した単価（2026-08-02 時点）

| モデル | 入力 /1M | **cached 入力 /1M** | 出力 /1M | 入力 modality | 最大入力 | 最大出力 |
|---|---:|---:|---:|---|---:|---:|
| `gpt-5.6-luna` | **$0.20** | **$0.02** | **$1.20** | text, image | 922,000 | 128,000 |
| `gpt-5.6-terra` | **$2.00** | **$0.20** | **$12.00** | text, image | 922,000 | 128,000 |

- 両モデルとも **Vision 対応**・**reasoning token support あり**
- 272,000 入力トークン超で **入力 2 倍・出力 1.5 倍**（1 リクエストが 4〜5K なので**適用されない**）
- cache write は uncached 入力の 1.25 倍
- **cached 入力が 1/10** なので、システムプロンプト＋生徒プロフィールの共通部分にプロンプトキャッシュが効けば入力コストが下がる。実際に効いているかは `usage.prompt_tokens_details.cached_tokens` で確認する

⚠️ **OpenRouter 経由だと現在この半額（luna $0.10/$0.60、terra $1/$6）**だが、
OpenRouter は「上流価格をマークアップなしで通す」と表明しているので、
これは**OpenRouter 側の期間限定プロモ**とみられる（terra には「50% off」表記がある）。
終了時期が公開されていないため、**恒久的な価格優位として計算に入れない。**

### 3-1. ⚠️ 未解決: 画像の `detail` が既定で `original`

GPT-5.6 系は `detail` を省略すると **`original` 相当**（パッチ/寸法上限までリサイズしない）になる。
現在のコードは `image_url` に `detail` を渡していないため、**スマホで撮った高解像度写真がそのままトークン化され、
terra の入力単価 $2/1M で課金される。**

| detail | 挙動 |
|---|---|
| `low` | 512×512 に縮小してから処理。低コスト・低レイテンシ |
| `original`（= 省略時 / `auto`） | リサイズしない。OCR・小さい文字の読み取り精度が高い |

**判断待ち**: 数式や手書きの文字を読む用途なので `original` の精度が必要な可能性が高い。
一方でコストとレイテンシに直結する。**画像 1 枚の実トークン数を実測してから決める**（→ §8）。
実測値が大きければ、送信前のリサイズ（長辺 1,024 など）を `processAttachments` に入れる選択肢もある。

### 3-2. 検証スクリプト

`scratchpad/check_llm.py`（Python 単体・外部依存なし・キーは `getpass` で対話入力）

①認証 ②**`/models` から実在モデル名を一覧表示** ③Chat（`reasoning_tokens` と `finish_reason` を表示、
`max_tokens` が 400 なら `max_completion_tokens` で自動再試行）④Vision（**PNG を実行時に生成**し、
`prompt_tokens` で画像 1 枚のトークン数を表示）⑤Embedding の次元

```bash
LLM_MODEL_DEFAULT='gpt-5.6-luna' LLM_MODEL_COMPLEX='gpt-5.6-terra' python3 check_llm.py
```

### 3-3. ⚠️ reasoning を切る実装が必要

luna / terra はどちらも **reasoning が既定 ON**（OpenRouter 上の `default_effort` は `medium`）。
effort は `max_tokens` の割合を消費し（`medium` ≈ 50%）、**reasoning トークンも出力として課金される**。

```
TUTOR_MAX_TOKENS = 1200  → 約 600 が思考に消え、生徒に見える回答は 600 程度
SUMMARY_MAX_TOKENS = 400 → 約 200 が思考 → 要約が 200 トークンしか出ない（実質破綻）
```

可視出力が空になると `openaiCompatibleClient.ts:74` が `AiResponseFailedError` を投げ、生徒には
`AI_RESPONSE_FAILED` が返る。**コストの問題ではなく、回答が壊れる問題。**

両モデルとも `"none"` を指定できるので切れるが、[現在のクライアントは `model` / `messages` /
`max_tokens` / `temperature` の 4 つしか送っていない](../../src/features/ai-answer/lib/llm/openaiCompatibleClient.ts)ので**コード変更が 1 点必要**。

なお GPT-5.6 系は `temperature` 非対応だが、Tutor 経路は `temperature` を渡していない
（`generateAnswer.ts:38` は `maxTokens` のみ）ので影響はない。

### 3-4. `MODEL_PRICING` への追記が必須

単価の照合ロジックは **完全一致 → `/` 以降のサフィックス** の 2 段だけ（`src/shared/lib/constants.ts:183` `findModelPrice`）。
登録済みは `deepseek-chat` / `gpt-4o-mini` / `gpt-4o` / `claude-haiku-4-5` / `claude-sonnet-4-6` のみで、
**luna / terra は未登録**。

未登録モデルを使うと **トークン数は記録されるのにコストが `$0.00` のまま積み上がり**、`/admin/usage` で暴走に気づけない。
しかも**記録済みのログは遡って再計算されない**（モデル変更時も同じ落とし穴）。

```ts
// src/shared/lib/constants.ts
const PRICE_GPT_5_6_LUNA: ModelPrice = { inputPerM: 0.2, outputPerM: 1.2 }
const PRICE_GPT_5_6_TERRA: ModelPrice = { inputPerM: 2, outputPerM: 12 }

export const MODEL_PRICING: Record<string, ModelPrice> = {
  // ...既存...
  'gpt-5.6-luna': PRICE_GPT_5_6_LUNA,
  'openai/gpt-5.6-luna': PRICE_GPT_5_6_LUNA,     // OpenRouter 形式でも引けるように両方入れる
  'gpt-5.6-terra': PRICE_GPT_5_6_TERRA,
  'openai/gpt-5.6-terra': PRICE_GPT_5_6_TERRA,
}
```

⚠️ 上記は **OpenAI 直の定価**。OpenRouter 経由（現在プロモで半額）にする場合は値が変わる。
`ModelPrice` に cached 入力の単価を持つ枠が無いため、**プロンプトキャッシュが効いた分は過大計上になる**
（安全側のズレ）。

追記後、`/admin/usage` の「単価が未登録のモデル」警告が消えることで確認できる。

## 4. コスト試算（生徒 20 名）

前提: 20 名 × 月 20 質問 = **月 400 質問**。1 USD = 150 円。

追加の前提: 画像付き質問の割合を **20%**（80 問）とする。画像付きは入力に **+1,500 トークン**を仮置き
（**実測前の仮値**。§3-1 のとおり `detail` が既定 `original` なので、実際はこれより大きい可能性がある）。

### 4-1. 1 問あたりの単価

| | 入力 | 出力 | **計** |
|---|---:|---:|---:|
| `gpt-5.6-luna`（テキスト） | 4,000 × $0.20/1M = $0.00080 | 500 × $1.20/1M = $0.00060 | **$0.00140** |
| `gpt-5.6-terra`（画像付き） | 5,500 × $2.00/1M = $0.01100 | 500 × $12.00/1M = $0.00600 | **$0.01700** |
| **加重平均（画像率 20%）** | | | **$0.00452 ≒ 0.68 円/問** |

### 4-2. 月額（画像率 3 シナリオ・reasoning を切った場合）

| 画像率 | luna（テキスト＋要約） | terra（画像） | **LLM 計** | インフラ込み合計 |
|---|---:|---:|---:|---:|
| 10%（40 問） | $0.53 | $0.68 | **$1.21** | 約 3,180 円 |
| **20%（80 問）** | $0.48 | $1.36 | **$1.84** | **約 3,280 円** |
| 30%（120 問） | $0.43 | $2.04 | **$2.47** | 約 3,370 円 |

画像率 20% の計算過程:

```
luna  入力 320×4,000 + 40×2,000 = 1.36M × $0.20 = $0.272
      出力 320×500   + 40×300   = 0.172M × $1.20 = $0.206   → $0.478
terra 入力 80×5,500 = 0.44M × $2  = $0.880
      出力 80×500   = 0.04M × $12 = $0.480                  → $1.360
```

reasoning を切らない場合（出力が最大 1,200/問）は **$2.7/月**。金額の差は月 130 円で無視できるが、
§3-3 のとおり**回答が壊れる**ので必ず切る。

### 4-3. 読み取り方

- **インフラ固定費（Vercel Pro $20）が全体の 92%。** Supabase Free なので $0
- **terra が LLM 代の 74% を占める**（画像は全質問の 2 割なのに、単価が luna の 10 倍）
  → コストを下げたいなら、モデル変更より**画像の `detail` / 解像度**を見直す方が効く（§3-1）
- モデルを変えても月数百円しか動かない → **モデルは品質で選ぶ**
- **Embedding のコストは管理画面に出ない**（`logUsage` は LLM 呼び出しでしか呼ばれない = `AC-12-01` 未実装）。
  実額は月 $0.001 規模（`text-embedding-3-small` で月 20k トークン程度）だが、
  **「管理画面のコストが実費の全部」と説明してはいけない**
- 生徒 200 名・月 8,000 質問なら LLM 代は 20 倍（約 $37）。インフラ固定費の支配は崩れる

### 4-4. コスト暴走の歯止め（実装済み）

| 機構 | 内容 |
|---|---|
| レート制限 | 生徒 1 人あたり直近 1 時間で 10 質問。超過分は **LLM を呼ぶ前に**定型文で返すので課金されない |
| 質問文の上限 | 6,000 文字超は LLM 呼び出し前に打ち切り（`MAX_QUESTION_CHARS`） |
| 出力上限 | 回答 1,200 トークン / 要約 400 トークン |
| 画像の上限 | 1 枚 20MB・1 メッセージ 3 枚・合計 8MB |
| 緊急停止 | 管理画面から即停止（デプロイ不要）。状態変化は `#alerts` に通知 |
| 再試行での二重課金なし | 生成済みの回答本文は保存され、リトライ時は配信のみやり直す |

**生徒 20 名 × レート制限 10 問/時**が理論上の天井なので、層 1（プロバイダ側の上限）が無くても
桁が跳ねない構造になっている。層 1 は「バグによる暴走を止める」役割に絞れる。

## 4-5. 支出上限の設定（3 層）

### 層 1: OpenAI 側

| 種類 | 挙動 | 設定パス |
|---|---|---|
| **Spend alert** | **通知のみ**・API トラフィックは継続 | `platform.openai.com/settings/organization/limits` → **Spend** → **Edit spend limit** |
| **Hard spend limit** | 該当リクエストが **429 + `organization_spend_limit_exceeded`** で失敗 | 同上 → **Enforce a hard limit** を ON |
| プロジェクト単位 | **429 + `project_spend_limit_exceeded`** | Project settings → **Limits** → Spend → Edit spend limit |

**両者は併存できる**（hard limit を追加してもアラートは有効なまま）。
なお OpenAI は使用ティアに応じた**承認済み月次上限**を別途割り当てており、これは設定した上限とは別枠。

**推奨値**（想定 $1.84/月 に対して）

| 設定 | 値 | 想定比 | 根拠 |
|---|---|---:|---|
| **Hard spend limit（月次）** | **$20** | 約 11 倍 | $20 ÷ $0.00452 = **約 4,425 質問**。生徒 20 名が 1 人あたり月 220 問投げないと届かない |
| Spend alert ① | **$5** | 約 3 倍 | 「何かおかしい」の早期検知 |
| Spend alert ② | **$12** | 約 6 倍 | 「調査が必要」。hard limit の手前で人が気づく |
| Auto recharge | **OFF** | — | 暴走時に無限にチャージされない |

**hard limit は高く・アラートは低く**設計する理由は、上限に達したときの挙動が重いため:

```
OpenAI が 429（organization_spend_limit_exceeded）を返す
  → mapOpenAiError が AiRateLimitedError にマップ（openaiCompatibleClient.ts:118）
  → processJob:54-55 が「レート制限用の長い待機」を選ぶ
  → 5秒 → 15秒 → 45秒 でリトライ（DEFAULT_MAX_ATTEMPTS = 3）
  → 約 65 秒後に失敗。全生徒に同時に起きる
```

⚠️ このとき `/admin/errors` に記録されるのは **`AI_RATE_LIMITED`** で、
「残高切れ／上限到達」か「プロバイダ側の一時的な混雑」かが**管理画面から区別できない**
（監査 `AC-11-01`: `raw_error` に provider の原因が入らない）。
**アラートメールが先に届いていれば切り分けられる**ので、$5 / $12 のアラートは実質的なデバッグ情報になる。

一方で暴走時には効く。バグでリトライループに入った場合の理論最大は
レート制限（20 名 × 10 問/時）× 1 問の最大コスト（terra で `max_tokens` 1200 を全部出力 = $0.0254）
= **約 $5/時 = $122/日**。$20 の hard limit なら**約 4 時間で止まる。**

### 生徒数が増えたときの再設定

**hard limit = 想定 LLM 代 × 10、ただし最低 $20**

## 5. ⚠️ Supabase Free で運用する場合のリスクと緩和策

| # | リスク | 実態 | 20 名規模での評価 | 緩和策 |
|---|---|---|---|---|
| 1 | **自動バックアップが無い** | Free にバックアップ機能なし | **最重要。** 生徒の会話ログ・プロフィール・レポート（個人情報）が消えたら復旧不能で、事故時に塾へ説明できない | **運用開始前に**週次 `pg_dump` の仕組みを用意する（GitHub Actions で定期実行 + Artifact 保存、または手動運用の手順書） |
| 2 | Storage 1GB / DB 500MB | 添付画像は `attachments` バケットに蓄積。**保持期間・自動削除の実装が無い**（`src/features/image-attachments/` に retention / cleanup 相当のコードは存在せず、ロールバック用 `remove` のみ） | 月 5 枚/人 × 2MB × 20 名 = 月 200MB → **約 5 ヶ月で 1GB 到達** | 保持期間を決めて古い添付を削除する運用を用意。または Storage が 700MB を超えた時点で Pro へ移行 |
| 3 | 7 日 inactive で一時停止 | 停止すると Bot が全生徒に無応答。復帰は手動操作 | 平日に生徒が使う限り停止しない。**危険なのは年末年始・お盆・春休み** | 長期休暇明けの初日に管理者が `/admin` を開いてから生徒に周知する、または休暇中に週 1 回 `/admin` を開く |

**判断**: 2 は 5 ヶ月後に効くので「Free で始めて閾値で Pro に上げる」で成立する。
**1 だけは最初から埋める。** バックアップ無しで個人情報を預かる状態を放置しない。

## 6. ⚠️ `LLM_MODEL_COMPLEX` 未設定時の実挙動（ガイドの記述が誤り）

セットアップガイドと `91_既知の制約.md` OBS-04 は「未設定だと画像がエラーも出さず無視され、テキストで回答する」と書いているが、**コードの実態が違う**。

```
executeProcessMessage.ts:212-213  useModel は LLM_MODEL_DEFAULT にフォールバック
executeProcessMessage.ts:303      imageDataUrls を「そのまま」generateAnswer に渡す  ← 画像を落としていない
```

画像データは非 Vision モデルへ送られるため、**多くのプロバイダは 400 で拒否 → 回答そのものが失敗する**（プロバイダ依存）。
さらに `executeProcessMessage.ts:228` のログは「生徒には『画像を読み取れない』旨を添えて回答しています」と書いているが、
`visionModelMissing` は `buildPrompt` に渡されていないので**そんな注記は付かない**（ログ文言自体が誤り）。

→ **`LLM_MODEL_COMPLEX` は任意ではなく必須扱いにする。** 修正対象の一覧は
`docs/05_その他/2026-08-02_未実装箇所監査.md` §0-2 に記載。

## 7. 環境変数の最終形

```bash
# --- 必須（6）これが無いとアプリが起動しない ---
NEXT_PUBLIC_SUPABASE_URL=          # URL 形式・末尾スラッシュなし・ビルド時にブラウザへ埋め込まれる
NEXT_PUBLIC_SUPABASE_ANON_KEY=     # ビルド時埋め込み
SUPABASE_SERVICE_ROLE_KEY=         # RLS を完全バイパス。NEXT_PUBLIC_ を絶対に付けない
SLACK_BOT_TOKEN=                   # xoxb-
SLACK_SIGNING_SECRET=              # 未設定だと /api/slack/events が 500 で Verified にならない
SLACK_BOT_USER_ID=                 # U 始まり。B 始まりを入れると Bot が永久に無反応

# --- AI 回答（4）OpenAI 直に一本化。base URL とキーは 2 モデルで共有される（§2） ---
LLM_API_KEY=                       # Embedding と同じキーを使える
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL_DEFAULT=gpt-5.6-luna     # $0.20/$1.20。Vision 対応。MODEL_PRICING に要追記（§3-4）
LLM_MODEL_COMPLEX=gpt-5.6-terra    # $2/$12。画像付き質問のみ。必須扱い（§6）

# --- RAG（3）3 つセットで設定する。1 つでも欠けると RAG は静かに無効化される ---
EMBEDDING_API_KEY=                 # LLM_API_KEY と同じ値でよい
EMBEDDING_BASE_URL=https://api.openai.com/v1
EMBEDDING_MODEL=text-embedding-3-small   # 1536 次元。2026-08-02 に実測で確認済み

# --- 任意（2） ---
SLACK_ALERTS_CHANNEL_ID=           # 未設定だと停止・再開の通知が飛ばない（操作自体は成功する）
SLACK_WORKSPACE_URL=               # 管理画面から Slack スレッドを開くリンク用

# --- 設定してはいけない / 不要（3） ---
# ANTHROPIC_API_KEY   … @anthropic-ai/sdk は依存から外してあるので使えない
# RESEND_API_KEY / RESEND_FROM_EMAIL … 参照コードが 0 件（将来の保護者メール用）
# SLACK_API_BASE_URL  … 受け入れテストのモック用。本番では設定しない
```

⚠️ **使わない変数は「空文字で登録」せず、行ごと作らない。**
env は起動時に Zod で一括検証しており、`*_BASE_URL` は URL 形式・`RESEND_FROM_EMAIL` はメール形式でないと
`Missing or invalid env vars: ...` を投げて **Slack Webhook を含むアプリ全体が 500 になる**。
「任意」の変数でも、空文字で存在する状態は「未設定」ではなく「不正な値」として扱われる。

`NEXT_PUBLIC_` の 2 つは**ビルド時にバンドルへ埋め込まれる**ため、Vercel で値を変えても再デプロイしないと反映されない。
