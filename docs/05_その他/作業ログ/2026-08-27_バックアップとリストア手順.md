## 判断したこと

- **Supabase CLI（`supabase db dump`）を主とし、`pg_dump` 直叩きは緊急手段に留めた**。
  理由は手順書 §2（pg_dump のバージョン合わせが不要 / CLI 固有のフィルタは手書き再現不能 / 既に devDependency）。
- **GitHub Actions のワークフローはこのリポジトリに置かない**。public リポジトリの artifact は
  認証なしで誰でもダウンロードできるため。YAML は手順書 §6 にコードブロックとして記載し、
  private リポジトリへコピーする前提にした。
- 保存先（private リポジトリ / R2 / 手動）は**未決定のまま**、スクリプトは保存先に依存しない形にした。
  決定後に必要な追加作業は手順書 §5。

## 見つけた不具合（重要）

1. **`supabase db dump` は既定でスキーマのみ**。既存の `step9` §9-7 が案内していた
   `supabase db dump -f backup.sql --linked` は**生徒データを 1 行も含まない**。
2. **`storage.buckets_vectors` / `storage.vector_indexes` の権限エラー**でデータリストアが丸ごと巻き戻る。
   最初のリストア試行は実際にこれで失敗した。スクリプト側で除外して解決（手順書 §7-1）。

## リストア検証

検証専用の Supabase スタックを `5435x` 帯に別途起動し（**既存のローカル DB には触っていない**）、
代表データ投入 → バックアップ取得 → `supabase db reset` で全損 → 復元 → 突き合わせを 1 周実施。
行数・内容の md5・embedding の次元と内積・自己参照 FK・RLS/ポリシー/インデックス/トリガー数・
`match_report_chunks` の動作・GRANT がすべて全損前と一致した。詳細は手順書 §8。
