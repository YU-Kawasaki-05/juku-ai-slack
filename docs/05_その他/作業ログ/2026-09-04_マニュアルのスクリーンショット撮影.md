## 撮影の方式（再撮影する人向け）

`node scripts/capture-manual-screenshots.mjs` の 1 コマンド。ヘッダコメントに手順あり。
スクリプトが自分でモックサーバーと `next start` を立てるので、Playwright の MCP は使わない。

要点だけ:

- **`fullPage: true` は効かない。** 管理画面は `h-screen overflow-hidden` +
  `main.overflow-y-auto` の構造。さらに `main` は `flex-1` なので `main.scrollHeight` を
  測っても縮まない（常にビューポート高が下限になる）。
  **`main` の子要素（`mx-auto max-w-6xl` のラッパ）の高さ**を測ってビューポートを伸ばす。
- **要素スクリーンショットも先にビューポートを伸ばす。** 伸ばさないと、ビューポートより
  下にある部分が白く抜ける（AI 用プロフィールのカードで踏んだ）。
- **横に広い表は幅 1460px で撮る。** 幅 1200px では `main` の実効幅が 928px にしかならず、
  ジョブ一覧の右端「操作」列（再実行ボタン）が隠れる。1460px にすると
  `max-w-6xl`（1152px）を使い切れる。
- **`--lang=ja-JP` を Chromium に渡す。** `<input type="date|month">` の表示書式は
  ブラウザ UI の言語で決まる。渡さないと `09/11/2026` / `August 2026` と英語式になる。
- **単価が `MODEL_PRICING` にあるモデル名で利用実績を作る。** ないと画面に
  「価格未設定のモデル」警告が出る。本番既定の `openai/gpt-5.6-luna` /
  `openai/gpt-5.6-terra` を使い、コストも実単価で計算している。
- **`REPORT_CHUNK_SEARCH_FAILED` は撮影後に消す。** `.env.test` が
  `EMBEDDING_BASE_URL` を到達しない URL に向けているせいで必ず出るテスト環境固有のログ。
  本番では起きないのでマニュアルのエラー一覧には載せない。

## サンプルデータの扱い

架空のデータのみ（`山田 太郎`・`佐藤 花子`・`鈴木 健一`、メールは `example.com`、
チャンネル ID は `C08TARO2026` など）。撮影用の管理者 `staff@example.com` も
その場で作って消す。E2E の恒久ユーザー（`e2e-admin` / `e2e-staff` / `e2e-logout`）は触らない。

`seed.sql` 由来の `テスト太郎` と `<REPLACE_CHANNEL_ID>` の紐付けが一覧に写ってしまうので、
**撮影前に既存行を JSON へ退避 → 全消し → 撮影 → サンプル削除 → 退避分を復元**という流れにした。
復元は `created_at` を含めた全カラムで行い、最後に退避時の内容と JSON 比較して照合する
（`[db] 復元を照合: 退避時と完全一致` が出れば成功）。失敗時も `catch` で同じ後片付けを走らせる。
退避 JSON は `os.tmpdir()` に置く（git status を汚さないため）。
