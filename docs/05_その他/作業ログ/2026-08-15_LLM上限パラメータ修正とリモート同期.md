# 2026-08-15 LLM 上限パラメータ修正とリモート同期

## 1. LLM の出力上限パラメータを自動フォールバック（commit 0a092c8）

`src/features/ai-answer/lib/llm/openaiCompatibleClient.ts`

- GPT-5 系 / o シリーズは `max_tokens` を 400 で拒否し `max_completion_tokens` を要求する。
  一方 gpt-4o 系や OpenAI 互換ゲートウェイ経由の非 OpenAI モデルは `max_tokens` しか
  受け付けず、未知パラメータを黙って無視する実装だと出力上限が効かなくなる。
- `preferredTokenParam()` でモデル名から初期推測（既定は広く通る `max_tokens`、
  `gpt-5*` / `o[1-9]*` のみ `max_completion_tokens`）。OpenRouter の `provider/model`
  形式にも対応。
- `isUnsupportedTokenParam()` は「そのパラメータ名が名指しされた 400」だけを検出する。
  別理由の 400 や 429 で再試行して二重課金しないため。
- 推測が外れたときのみ 1 回入れ替えて再試行し、結果をプロセス内 Map にキャッシュする。

検証: `pnpm vitest run src/features/ai-answer/lib/llm/openaiCompatibleClient.test.ts`（19 passed）、
`pnpm typecheck` 通過。
