## 監査で分かった主要な事実

1. **P0 は 2 件、いずれも FR-08**。AC-08-01（月次レポート自動生成）と AC-08-02（承認後の Slack 送信）。
   後者は `ReportForm.tsx:279` が「Slack 送信の対象になります」と表示して保存成功トーストで終わるのに
   **何も投稿されない**サイレント失敗。`status='sent'` に到達する経路が無いため送信済みバナーと
   送信済みフィルタはデッド UI。

2. **トピック検出の不在が 14 件の到達不能を連鎖させている**。`getMastery(db, personId, null)` が常に
   `P_MASTERY_DEFAULT = 0.2` を返す → `selectMode` が direct 固定 → Evaluator 不起動 → BKT 更新なし →
   FR-25（誤概念リマインダー）のデータ源も永久に空。FR-05 / FR-23 / FR-25 / FR-26 が連鎖して死んでいる。

3. **`docs/02_外部設計/00_サマリー.md:42` が「AC-08 全件 ✅」と宣言している**（実態は AC-08-01/02 未実装）。
   ドキュメントだけを読むと実装済みと誤読する、最も危険なドリフト。

4. **`LLM_MODEL_COMPLEX` 未設定時の挙動が、セットアップガイドの記述と違う**。
   `executeProcessMessage.ts:303` は `imageDataUrls` をそのまま `LLM_MODEL_DEFAULT` へ送るため、
   「画像が黙って無視される」ではなく**プロバイダ依存で 400 → 回答自体が失敗しうる**。
   さらに同 228 行のログは「生徒には『画像を読み取れない』旨を添えて回答しています」と書いているが、
   `visionModelMissing` はプロンプトに渡されていないので**そんな注記は付かない**（ログ文言自体が誤り）。
   → `docs/06_セットアップガイド/step1_事前準備.html` / `step5_vercelデプロイ.html` /
   `docs/07_受け入れテスト/91_既知の制約.md` OBS-04 の記述を要修正。

## LLM プロバイダの選定（同日・別作業）

OpenRouter 前提で進めていたが、調査の結果 **OpenAI 直に一本化**へ方針変更した。

- **`gpt-5.6-luna` が Vision 対応かつ安価（$0.20/$1.20）**とわかり、1 モデルで DEFAULT と COMPLEX を
  兼ねられるため、当初 OpenRouter を選んだ理由（別プロバイダのモデル混在）が消えた
- OpenRouter は `provider.data_collection` の**既定が `"allow"`**で、守るにはリクエストごとの明示送信＝
  コード変更が必要。かつ DeepSeek 一次プロバイダは `training: true` / `retainsPrompts: true`
- 調査記録は **`docs/05_その他/2026-08-02_OpenRouter導入要件.md`**（主張 115 件・出典照合 107 件）に保存。
  再検討時に調査をやり直さないため
- **OpenAI 直の定価は OpenRouter の 2 倍**（luna $0.20/$1.20 対 $0.10/$0.60）。
  OpenRouter は「マークアップなしで上流価格を通す」と表明しているので、現在の半額は
  **OpenRouter 側の期間限定プロモ**とみられる。恒久的な価格優位として計算に入れない方針

実測で確認できたこと（2026-08-02）:

- OpenAI キーは有効・クレジットチャージ済み
- **`text-embedding-3-small` が 1536 次元で応答** → RAG の前提条件クリア
- テキスト生成は疎通済み

新たに見つかった問題:

- **GPT-5.6 系は `detail` 省略時が `original` 相当**（リサイズなし）。現在のコードは `detail` を渡していないため、
  高解像度のスマホ写真がそのままトークン化され terra の $2/1M で課金される。**画像 1 枚の実トークン数は未実測**
- luna / terra はどちらも **reasoning が既定 ON**。`TUTOR_MAX_TOKENS = 1200` の約半分が思考に消え、
  `SUMMARY_MAX_TOKENS = 400` では要約が実質破綻する。**コード変更 1 点（reasoning を切る）が必須**

支出上限の推奨値（想定 $1.84/月）:

- **Hard spend limit $20**（約 4,425 質問分 = 想定の 11 倍）／アラート $5・$12／Auto recharge OFF
- 上限到達は **429 + `organization_spend_limit_exceeded`** → 既存コードは `AI_RATE_LIMITED` として
  5 秒→15 秒→45 秒でリトライし約 65 秒後に失敗する。`/admin/errors` ではプロバイダ側の混雑と区別できないため、
  アラートメールが実質的なデバッグ情報になる
