# 2026-07-08 FR-20 スレッド長期要約（Phase 3）

## 概要

長いスレッド（10往復超）の古いやり取りを累積要約し `thread_summary` に保存、以降のプロンプトで
「要約 + 直近」を使う機能（FR-20, P1）。バックエンド領域。feature/thread-summary ブランチで実装。

## 進め方（Ultracode: Workflow 活用）

1. **調査（Workflow 並列4領域）**: 既存パイプライン（executeProcessMessage / threadHistory /
   buildPrompt・LLM / schema）を精査。after() は route.ts のみ＝execute は既に非同期文脈内、
   挿し込みは runEvaluator 直後、10往復=20行、thread_summary は未書き込みでプロンプト未使用、等を把握。
2. **設計 → 実装**: 純関数 planSummary/buildSummaryPrompt を分離。返信後ベストエフォートで summarizeThread。
3. **adversarial レビュー（Workflow 4観点）**: 正確性/PII/コスト/回帰。**HIGH 3件**を検出し再設計。

## adversarial レビューで見つかった初版の欠陥と修正

| 深刻度 | 欠陥 | 修正 |
|--------|------|------|
| HIGH | 要約境界と直近履歴窓の間に**文脈欠落**（KEEP 固定窓） | `summary_message_count` を永続化し、履歴は「要約済み接頭辞の後ろ全部」を読む（穴ゼロ） |
| HIGH | **PII 越境**: 再割当てで生徒Aの要約が生徒Bに漏れる | 要約の読込・生成・UPDATE すべてに person_id 条件。person 不一致時は要約を注入も生成もしない |
| HIGH | 剰余一致トリガーが件数**奇数化で恒久停止** | 「総数 − 要約済み ≥ 20」の単調・冪等条件に |
| LOW | 要約失敗が AI_RESPONSE_FAILED を汚染 | 専用コード `THREAD_SUMMARY_FAILED`（warning）を新設 |
| LOW | UPDATE が person 無条件 / range と count の role 不一致 / SUMMARY_SYSTEM に内部情報ガード無し | すべて修正 |

## 実装

- `summary_message_count`（migration 025 + database.types 手動反映）
- `summarizeThread`（planSummary 単調トリガー・累積要約・person ガード付き UPDATE）
- `countThreadMessages` / `loadMessageRange`（role フィルタ整合）
- `buildPrompt` に threadSummary 注入、`generateAnswer` 透過
- `executeProcessMessage`: person 一致時のみ要約経路。履歴は要約済み接頭辞以降を loadMessageRange で取得
