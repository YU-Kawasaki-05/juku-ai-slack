# 2026-08-02 E2E 基盤整備（ローカル一発実行 + 認証後フロー）

## 背景

E2E は「認証境界 10 件 + ログイン UX 4 件」しか動かず、認証後フローは
`TEST_ADMIN_*` 未設定 + seed に auth ユーザーが無いため恒久 skip だった。
さらにローカル Supabase が他プロジェクト（premake）とポート衝突して起動できなかった。

目標: **`pnpm test:e2e` 一発で全部通る**ところまで持っていく。

### 2. E2E 用 env

- `.env.test.example`（コミット対象）にローカル Supabase の URL / anon / service_role、
  ダミー Slack 値、テストユーザーの認証情報をまとめた。`.env.test` は gitignore。
- `scripts/test-env.mjs` が `.env.test` →（無ければ）`.env.test.example` の順で読む。
  **既に process.env にある値は上書きしない**（CI/シェルの一時上書きが勝つ）。
- `playwright.config.ts` の `webServer.env` にこの値を最後に重ねるので、
  本番の `.env.local` が E2E に混ざらない。
- LLM / Embedding は**あえて未設定**。外部 API を叩かせないため。
  副作用としてレポート保存時の自動 Embedding が必ず失敗するので、
  詳細ページの「Embedding 再生成が必要です」警告経路がそのまま検証対象になる。

### 3. テストユーザーの自動作成（`e2e/global-setup.ts`）

Supabase Admin API（service_role）で admin / staff / logout の 3 ユーザーを冪等に upsert し、
`app_metadata.role` を付与する（`requireAdmin` はここを見る。`user_metadata` では昇格不可）。
admin / staff は実際に `/login` を通して storageState を保存。
`seed.sql` は本番想定なので触っていない。

**logout 専用ユーザーを分けた理由**: `supabase.auth.signOut()` は既定で `scope: 'global'`。
admin と共有すると、ログアウトのテストが並列実行中の全 admin テストのセッションを巻き添えで
失効させる（実際に 17 件が落ちた）。

### 4. ビルドと webServer の自動化

- `pnpm test:e2e` = `next build` → `playwright test`（`scripts/with-test-env.mjs` 経由）。
  ビルド省略は `pnpm test:e2e:nobuild`。
- `reuseExistingServer` を **CI 外でも `false`** に変更。古いビルドを配信中のサーバーを
  黙って使い回す事故を防ぐ（実際に 02:39 起動の孤児 `next-server` が 3200 を掴んでいた）。
- `expect.timeout` を 10 秒、テスト timeout を 60 秒に。管理画面は全ページ SSR + 複数クエリで、
  ワーカー並列時にクライアント遷移後の描画が 5 秒を超えることがあったため。

## 見つけたバグ（修正済み）

### レポート編集画面で「承認して保存」を押しても下書きのまま保存される

`ReportForm` の `<input type="hidden" name="id">` が **`form.id` を覆い隠していた**。
HTMLFormElement は `[LegacyOverrideBuiltIns]` なので、`name="id"` のコントロールが
`Element.prototype.id` より優先される。

React の `createFormDataWithSubmitter` は submitter の name/value を FormData に載せるとき

```js
if (form.id) temp.setAttribute('form', form.id)
```

を通る。ここで `form.id` が文字列ではなく `HTMLInputElement` になるため、
temp input の form owner が `"[object HTMLInputElement]"` という存在しない ID に向き、
**submitter（`name="status"`）が FormData から丸ごと消える**。
結果 `readForm` の `formData.get('status') ?? 'draft'` が効いて常に下書き保存になっていた。

- 影響: 編集画面からレポートを**承認できない**（= RAG 参照対象にできない）。新規作成は正常。
- 修正: hidden フィールドを `name="reportId"` にリネーム（`ReportForm.tsx` / `reportActions.ts` / 単体テスト）。
- 再発防止: `e2e/reports.spec.ts` の「下書き作成 → … → 承認保存」が回帰テストになる。
- 同じ `name="id"` パターンは他 6 フォームにもあるが、いずれも submitter に name/value が無いので影響なし。

## CI

`.github/workflows/ci.yml` の e2e ジョブを、本番 Supabase の secrets ではなく
**ローカル Supabase**（`supabase start` → `db reset` → `pnpm test:e2e`）で回す形に変更。
env は `.env.test.example` が読まれるので secrets 不要。失敗時は playwright-report を artifact に上げ、
`always()` で `supabase stop --project-id juku-ai-slack` する。main push 限定は維持。

## 引き継ぎ

- ローカル Supabase は起動したままにしてある（`pnpm supabase:stop` で停止）。
- `pnpm test:e2e` は `.next` を E2E 用 env でビルドし直す。実行後に `pnpm start` すると
  ローカル Supabase 向けのビルドが動くので、通常の開発は `pnpm dev` を使うこと。
- Slack イベントの本処理（event_callback → LLM）は未カバー。LLM モックが要るので受入テストフェーズで。
