# ローンチ計画 — juku-ai-slack-bot

## 1. フェーズ別ローンチ

### Phase 1: 内部α（1名テスト）
- **目的**: 単一の生徒チャンネルで基本的なBotの動作を確認
- **対象**: 開発者自身 or 協力者1名
- **期間**: Sprint 2完了後（約2ヶ月後）
- **スコープ**: FR-01〜05（Slack受信・AI回答）のみ
- **インフラ**: Vercel Preview + Supabase Free

### Phase 2: 限定β（5名テスト）
- **目的**: RAG・画像対応・管理画面の実運用検証
- **対象**: 塾スタッフ1〜2名 + 生徒3〜4名
- **期間**: Sprint 6完了後（約4ヶ月後）
- **スコープ**: FR-01〜17（全P0機能）
- **インフラ**: Vercel Pro + Supabase Free（`maxDuration=300` を使うため Hobby では関数が 60 秒で kill される）

### Phase 3: 正式ローンチ（全生徒）
- **目的**: 全生徒への本番展開
- **対象**: 塾在籍生徒全員
- **期間**: β後のバグ修正・改善完了後
- **スコープ**: 全P0機能 + 必要に応じP1追加
- **インフラ**: Vercel Pro + Supabase Free（生徒数次第でPro移行）

### 2.5 ロールバック手順
- 問題発生時: Vercelダッシュボードから直前のデプロイに1クリックでロールバック
- DBマイグレーション: Supabaseで手動でロールバックSQLを実行（事前に準備）
- **Bot の AI 応答停止**: `/admin` の KillSwitchCard から「AI応答を停止」（**再デプロイ不要・即時反映**。`#alerts` に通知される）
  - 環境変数の書き換え＋再デプロイは不要になった（`ENABLE_AI` は廃止済み）

## 4. 生徒・スタッフへのオンボーディング

### 生徒向け案内（Slack DM or チャンネル投稿）

```
こんにちは！勉強サポートBot「〇〇先生」を使い始めます。

【使い方】
・このチャンネルで @先生 とメンションして質問してください
・写真（問題用紙）を一緒に送ることもできます
・スレッドで返信するとそのまま会話が続きます

【できないこと】
・テストの答えをそのまま教えることはできません（ヒント形式で返答します）
・学習内容以外の質問への回答

質問があればスタッフまで！
```

### スタッフ向け操作手順書
- 管理画面へのログイン方法
- 新規生徒の追加・チャンネル紐付け手順
- レポートの登録・公開手順
- エラー一覧の確認・対応済みマーク手順
- `/admin/jobs` での滞留ジョブのスイープ・失敗ジョブの再実行手順
- AI 応答の停止・再開（`/admin` の KillSwitchCard。**管理者のみ**）

> 環境構築そのものの手順は `docs/06_セットアップガイド/index.html`（新規セットアップの正本）、
> 管理画面の運用前設定は `docs/03_技術設計/04_セットアップ手順.md`。

## 5. リスクシナリオと事前対策

| リスク | 確率 | 対策 |
|--------|------|------|
| ローンチ直後のコスト急増 | 中 | per-person レート制限（10回/時）で上限を作り、`/admin` を日次で見て kill_switch から手動停止（自動停止は無い） |
| 生徒が不適切な質問を送信 | 中 | AIシステムプロンプトでスコープ限定 |
| スタッフがチャンネル紐付けを間違える | 高 | UNIQUE制約 + 管理画面で確認UIを整備 |
| `after()` が実行時間上限で kill されジョブが滞留する | 中 | `/admin/jobs` のスイープが processing 10分 / pending 15分超を `JOB_TIMEOUT` で回収 → 「再実行」（Cron は使っていない: DEC-13） |
| 単価未登録モデルに切り替えてコストが見えなくなる | 中 | `MODEL_PRICING`（`src/shared/lib/constants.ts`）を更新。プロバイダ側の請求と突き合わせる |
| Slack Botが他のワークスペースに招待される | 低 | 単一ワークスペース設計（検証は省略）|
