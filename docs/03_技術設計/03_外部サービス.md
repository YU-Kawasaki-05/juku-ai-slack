## 2. 各サービス詳細

### 2.1 Slack API

**目的**: メッセージ受信・返信・リアクション・添付ファイルダウンロード

**接続方式**: HTTP Events API（Webhook）。Socket Mode / App-Level Token は不要。

**Bot Token Scopes**（実際に呼んでいる API から逆算した必要最小セット）:

| scope | 必要な理由 | 実装 |
|-------|-----------|------|
| `chat:write` | 回答・エラー文言・#alerts 通知の投稿 | `chat.postMessage`（`src/shared/lib/slack/client.ts`） |
| `reactions:write` | 処理中の 🤔（`thinking_face`）付与・除去 | `reactions.add` / `reactions.remove`（同上） |
| `files:read` | 添付画像の `url_private` を Bot Token でダウンロード | `src/features/image-attachments/lib/downloadSlackFile.ts` |
| `channels:history` | 公開チャンネルの `message.channels` イベント購読に必須 | イベント購読側の要件 |
| `groups:history` | 生徒チャンネルを**非公開**にする場合のみ追加 | 同上（`message.groups`） |

> `channels:read` / `users:read` は **不要**。`conversations.*` も `users.*` も 1 箇所も呼んでいない。
> チャンネル名は `slack_channel_bindings.slack_channel_name`（管理画面で手入力）を表示用に持つだけで、
> 信頼の基点は常に `channel_id`（BR-07-01）。スレッド履歴も Slack ではなく `slack_messages` テーブルから読む。

**Event Subscriptions**:
- Request URL: `https://{your-domain}/api/slack/events`
- Subscribe to bot events: `message.channels`（非公開チャンネルを使うなら `message.groups` も）
- **`app_mention` の購読は不要**。メンション判定は本文に `SLACK_BOT_USER_ID` が含まれるかの文字列一致で行う（`src/features/slack-events/lib/eventFacts.ts`）

**運用上の必須作業**: Bot を各生徒チャンネルに `/invite` すること（招待していないチャンネルのイベントは届かない）。

**環境変数**:
```
SLACK_BOT_TOKEN=xoxb-xxxxx
SLACK_SIGNING_SECRET=xxxxx
SLACK_BOT_USER_ID=U_BOTID          # BotのSlack User ID（メンション検出用）
SLACK_WORKSPACE_URL=https://...    # 任意。/admin/errors の「Slack で開く」リンク用
SLACK_ALERTS_CHANNEL_ID=C0XXXXXXXX # 任意。kill_switch の停止・再開を通知する #alerts（DEC-15）
```

**制約**:
- Events API: Slack 側のリトライあり（3秒以内に ACK 必須）。受信ハンドラは署名検証 → 重複排除 → ジョブ登録 → 即 ACK し、AI 処理は `after()` に逃がす
- ファイル URL: `url_private` は Bot Token が必要。ダウンロードはホスト allowlist（`slack.com` / `*.slack.com`）+ `redirect: 'manual'` + 30秒タイムアウト
- Web API 呼び出しは 10 秒タイムアウト。429 は `Retry-After` を尊重

### 2.2 Supabase

**目的**: PostgreSQL DB + pgvector + Auth + Storage

**プラン**:
- MVP開始: Free（500MB DB・1GB Storage）
- 成長後: Pro $25/月（8GB DB・100GB Storage）

**必要な設定**: 大半は migration が実施する。手作業は Auth 周りのみ。

| 項目 | 方法 |
|------|------|
| pgvector 拡張 | `004_enable_pgvector.sql`（`CREATE EXTENSION IF NOT EXISTS vector`） |
| Storage bucket `attachments`（private） | `022_create_attachments_bucket.sql` |
| RLS ポリシー | `014` / `015` / `026`。`026` で「staff/admin の SELECT のみ」に絞り、authenticated の書き込みは全剥奪 |
| **サインアップ無効化** | **手作業・必須**。Dashboard > Authentication > Sign In / Providers > 「Allow new users to sign up」を OFF（`026` のヘッダ参照） |
| 管理画面ユーザー | 招待制。`app_metadata.role` に `staff` / `admin` を必ず設定（`user_metadata` は自己昇格できるので使わない） |
| Service Role Key の取得 | Dashboard > Settings > API |

**環境変数**:
```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=xxxxx    # ブラウザ用（公開可。用途は signIn/signOut のみ）
SUPABASE_SERVICE_ROLE_KEY=xxxxx        # サーバーのみ・絶対に公開しない
```

**制約**:
- Free: 同時接続50、1週間非アクティブで DB が一時停止
- pgvector: `report_chunks` は `vector(1536)`。ivfflat インデックスは小規模データでリコールが落ちるため `027` で DROP 済み（seq scan で十分）。データ量が増えたら再作成する

### 2.3 Vercel

**目的**: Next.js ホスティング + Serverless Functions + `after()` によるバックグラウンド実行

**プラン**: Pro $20/月。`export const maxDuration = 300`（`src/app/api/slack/events/route.ts`）を使うため Hobby の関数上限（60秒）では足りない。

> **DEC-13**: ジョブ Worker は Vercel Cron ではなく「バックグラウンド実行 + `jobs` テーブル」で実装する。
> Cron は最短1分間隔の制約があり応答遅延が大きい（最悪75秒）。
> Webhook 受信直後にバックグラウンド実行するため 15〜30秒で返信できる。
> `jobs` テーブルは維持してリトライ・ログ・管理画面での確認を継続する。

**実装は `@vercel/functions` の `waitUntil` ではなく Next.js の `after()`**（`next/server`）:

```typescript
// src/app/api/slack/events/route.ts
import { after, NextResponse } from 'next/server'

export const runtime = 'nodejs'
export const maxDuration = 300   // A-1: AI 処理が既定の実行時間上限で kill されるのを防ぐ

export async function POST(req: Request): Promise<NextResponse> {
  // 署名検証 → 重複排除 → binding/session 解決 → enqueueJob
  after(async () => { /* try/catch で包み、失敗は logError に残す */ })
  return NextResponse.json({ ok: true })   // 3秒以内に ACK
}
```

- `@vercel/functions` は依存に入っていない。フレームワーク標準の `after()` に一本化している
- `after()` のコールバックは誰も await しないため、`route.ts` の `safeAfter()` で必ず try/catch し `ai_error_logs` に残す（A-2）
- **Cron は 1 本も使っていない**。`vercel.json` は存在せず、`/api/cron/*` も無い。滞留ジョブの回収・古い行の掃除は `/admin/jobs` の画面表示時（60秒スロットル）と手動ボタンで行う

### 2.4 LLM API（OpenAI 互換）

**プロバイダ非依存**。`src/features/ai-answer/lib/llm/getLlmClient.ts` が `openai` SDK の OpenAI 互換クライアントを 1 種類だけ生成し、`LLM_BASE_URL` の差し替えでプロバイダを切り替える。Anthropic 直アダプタは未実装（`@anthropic-ai/sdk` は依存から外してある）。

**モデルの使い分け（実装済みの分岐は 2 つだけ）**:

| 用途 | 使う env | 実装 |
|------|---------|------|
| 通常の質問・要約・Evaluator | `LLM_MODEL_DEFAULT` | `executeProcessMessage.ts` / `summarizeThread.ts` / `evaluate.ts` |
| **画像あり**の質問（Vision） | `LLM_MODEL_COMPLEX`（未設定なら DEFAULT にフォールバック + warn） | `executeProcessMessage.ts`（BR-05-15） |
| Embedding 生成 | `EMBEDDING_MODEL` | `embeddingClient.ts` |

> 旧設計の `LLM_MODEL_VISION` は存在しない。**Vision 用は `LLM_MODEL_COMPLEX`** に統合されている。

**単価テーブル**: `src/shared/lib/constants.ts` の `MODEL_PRICING`（USD / 100万トークン）。
`findModelPrice()` が「完全一致 → `/` 以降のサフィックス」の順で照合するため、OpenRouter 形式（`provider/model`）でも素の名前が登録されていれば当たる。

| モデル | input | output |
|--------|-------|--------|
| `claude-haiku-4-5` | $1.0 | $5.0 |
| `claude-sonnet-4-6` | $3.0 | $15.0 |
| `gpt-4o-mini` | $0.15 | $0.6 |
| `gpt-4o` | $2.5 | $10.0 |
| `deepseek-chat` | $0.27 | $1.1 |

> 未登録モデルは `estimated_cost = 0` で記録される（トークン数は常に記録される）。
> 現状 UI 上で「単価未登録」を警告する表示は無い（Phase 2 提案）。**新しいモデルに切り替えたら `MODEL_PRICING` を更新すること。**

**コスト試算**（`.env.example` の既定構成 = default: `deepseek/deepseek-chat`, complex: `openai/gpt-4o`。生徒50人×週5質問×4週）:
```
月間質問数: 50人 × 5問/週 × 4週 = 1,000問
通常質問 (700問): input 1,500tok + output 500tok
画像質問 (300問): input 2,500tok + output 800tok

deepseek-chat ($0.27/M input, $1.1/M output):
  700問 × 1,500tok = 1,050k input → $0.28
  700問 ×   500tok =   350k output → $0.39

gpt-4o ($2.5/M input, $10/M output):
  300問 × 2,500tok =   750k input → $1.88
  300問 ×   800tok =   240k output → $2.40

Embedding (text-embedding-3-small $0.02/M):
  1,000チャンク × 500tok = 500k → $0.01

月額合計（推定）: ~$5
```
- スレッド長期要約（`SUMMARY_MAX_TOKENS=400`）が加算される。頻度は「未要約が20件到達ごと」
- Evaluator は **現状 1 度も起動しない**（モードが常に `direct` のため。FR-05 / FR-23 の未実装部分）。socratic / confirmation が実働するとコストは上振れする
- 暴走時は `kill_switches`（下記）と per-person レート制限（10回/時）で止める

**環境変数**:
```
LLM_API_KEY=xxxxx
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL_DEFAULT=deepseek/deepseek-chat
LLM_MODEL_COMPLEX=openai/gpt-4o          # 画像あり質問（Vision）用
```

> `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` を直接読むコードは存在しない。
> `ANTHROPIC_API_KEY` は env スキーマ上 optional として残っているが、参照している実装は無い。

### 2.5 Embedding API（OpenAI 互換）

**目的**: レポート本文のチャンクをベクトル化して RAG（FR-10）に使う。レポート保存時に自動再生成（DEC-14）。

- クライアント: `src/features/reports/lib/embeddingClient.ts`（`openai` SDK、`encoding_format: 'float'` 明示、`index` 昇順ソート、件数・次元検証あり）
- 次元は `EMBEDDING_DIM = 1536`（`report_chunks.embedding vector(1536)` と一致させること）
- **未設定でも管理画面・Bot は動く**。`EmbeddingNotConfiguredError`（severity=info）で RAG をスキップし、エラーログ洪水を避ける

```
EMBEDDING_API_KEY=xxxxx
EMBEDDING_BASE_URL=https://api.openai.com/v1
EMBEDDING_MODEL=text-embedding-3-small
```

### 2.6 AI キルスイッチ（環境変数ではなく DB）

`ENABLE_AI` という環境変数は**存在しない**。停止・再開は DB とアプリ内 UI で行う（DEC-15）。

- テーブル: `kill_switches`（`031_create_kill_switches.sql`）。列は `name / enabled / reason / updated_at / updated_by`。シードは `('ai_responses', true)` の 1 行
- チェック: `src/features/kill-switch/lib/killSwitch.ts` の `isAIEnabled()` を `processJob` 冒頭（claim 後・🤔 付与前）で評価。**読み取り失敗時は fail-open**（AI を止めない）
- 停止中の挙動: 🤔 を付けず、`AI_PAUSED` の定型文だけを返し、ジョブは `completed`（`error_code='AI_PAUSED'`）で終える。LLM は呼ばない
- 操作 UI: `/admin`（ダッシュボード最上部の KillSwitchCard）。**トグルは `requireAdmin`**（staff はカードを見られるが操作は拒否される）
- 通知: 状態が変化したときだけ `SLACK_ALERTS_CHANNEL_ID` へ投稿。未設定なら通知をスキップして `console.warn`（トグル自体は成功する）

## 5. リスクと代替策

| サービス | リスク | 代替 |
|---------|--------|------|
| LLM プロバイダ | レートリミット・サービス停止・値上げ | `LLM_BASE_URL` + `LLM_MODEL_*` の差し替えのみで切替可能（OpenAI 互換の範囲内）。切替時は `MODEL_PRICING` の更新を忘れないこと |
| Embedding プロバイダ | モデル変更・次元数変更 | 次元が変わると `report_chunks.embedding vector(1536)` と `EMBEDDING_DIM` の両方を migration で変更し、全レポートを再生成する必要がある |
| Supabase | サービス停止 | Neon + Pinecone（移行コスト高） |
| Vercel | 関数タイムアウト・プラン制約 | `maxDuration=300` を満たせるホスティングが前提。滞留ジョブは `/admin/jobs` のスイーパで回収できる |
| Slack API | Bot token 失効 | env 更新 + 再デプロイ。失効中のイベントは `slack_event_receipts` に残るが自動再処理はしない |
| 外部 APM 未導入 | 障害の初動が遅れる | `/admin/errors` の severity フィルタと `/admin/jobs` の KPI カードを日次で確認する運用でカバー（Phase 2 で再検討） |
