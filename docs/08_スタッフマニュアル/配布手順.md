# スタッフマニュアルの配り方

このフォルダ（`docs/08_スタッフマニュアル/`）は静的サイトとして配れる。
外部のCDNやフォントを一切参照していないことを確認済みなので、置くだけで動く。
**ただし、このファイル（`配布手順.md`）は開発者向けなので、スタッフ向けの公開には含めない**
（下の 1. の手順で、コピーするときに除く。フォルダごと上げると `/配布手順.md` で誰でも読めてしまう）。

配布先は **Cloudflare Pages**（2026-09-12 本人判断・ops の Q-0060「Cloudflareかな」）。
検索に載せない扱いにしてある: 各ページの `<meta name="robots" content="noindex, nofollow">` と、
Pages 用の `_headers`（`X-Robots-Tag`）の二重。

---

## 1. Cloudflare Pages に上げる

Cloudflare のアカウントにログインする必要があるので、**この手順は人がやる**
（ブラウザのOAuthが要るため、AIからは実行できない）。

```
cd ~/develop/marujuku-slack
rm -rf /tmp/juku-manual-dist
rsync -a --exclude '配布手順.md' docs/08_スタッフマニュアル/ /tmp/juku-manual-dist/   # 配布手順.md を除いてコピー
npx wrangler@4 login                                  # 初回のみ。ブラウザが開く
npx wrangler@4 pages deploy /tmp/juku-manual-dist \
  --project-name juku-ai-manual
```

初回は「プロジェクトを作るか」と本番ブランチを聞かれるので、作成して `main` を選ぶ。
`https://juku-ai-manual.pages.dev` のような URL が出る。**これがスタッフに渡す URL。**

更新したいときは同じ `pages deploy` をもう一度叩けばよい（上書きされる）。

## 2. 見せる相手を絞る場合（任意）

`noindex` は検索に載らないだけで、URL を知っていれば誰でも開ける。
**閲覧できる人をメールアドレスで限定したい場合**は Cloudflare Access を使う。
Zero Trust の無料枠で50人まで使える。

1. Cloudflare ダッシュボード → Zero Trust → Access → Applications → Add an application
2. Self-hosted を選び、ドメインに `juku-ai-manual.pages.dev` を入れる
3. Policy を1つ作り、Include に **Emails** で塾のスタッフのアドレスを列挙する
4. 保存すると、以降その URL はメール認証（ワンタイムコード）を通らないと開けなくなる

⚠️ この場合、スタッフは**マニュアルを見るためにもう1回メール認証をする**ことになる。
手間が増えるので、「URL を知っている人だけが見られればよい」なら 1. だけで止めてよい。
どちらにするかは配る直前に決める。

## 3. スタッフに渡すもの（2点セット）

| 渡すもの | 経路 | 注意 |
|---|---|---|
| マニュアルの URL | Slack のチャンネルでもDMでもよい | 上の Pages の URL |
| 招待リンク | **Slack の DM だけ**。チャンネルに貼らない | 60分・1回限り |

招待リンクの発行（塾の管理者から、新しい人の「名前・メールアドレス・役割（管理者／スタッフ）」が
Slack の DM で届いたら、それをもとに発行する。パスワードは誰にも渡さず、本人が自分で決める）:

```
node scripts/invite-staff.mjs --email <その人のアドレス> --role staff \
  --app-url https://juku-ai-slack.vercel.app
```

⚠️ **招待リンクは、それ単体でそのアカウントにログインできる資格情報。**
リンクを送るときは「**転送しないでください**」と必ず添える。
ターミナルの出力ごとコピーして共有しない。

⚠️ **既にアカウントがある人に再発行するときは `--role` を今の役割と同じにする。**
違う役割を指定すると役割が変わる（admin の人に `--role staff` を指定すると
管理権限が消える）。役割が変わる指定は既定で中止するようにしてあるので、
中止されたらメッセージのとおりに `--role` を直すこと。

## 4. 配る前に1回だけ確認する

```
pnpm check:deployment -- --app-url https://juku-ai-slack.vercel.app
```

NG が出たまま配ると、スタッフが詰まって「使えないもの」という第一印象になる。
特に**招待リンクの着地先**は、未登録でもエラーにならず黙って別の場所に飛ぶので、
人の目では気づけない。

あわせて、次の2点は**本番でまだ通した記録がない**ので、配る前に1回ずつ試す。

1. **招待リンクを Slack の DM に貼って開けるか。** 自分宛てのテスト用アドレスで招待リンクを発行し、
   自分に DM して開く。Slack がリンクのプレビューを取りに行って、1回限りのリンクを使い切っていないかを見る
   （`scripts/verify-invite-flow.mjs` は Slack を通していない）。
2. **第4章の「承認 → 最終 Embedding に日時が入る」。** テスト用の生徒でレポートを承認し、詳細画面の
   「最終 Embedding」に日時が入ることを見る（`EMBEDDING_*` の環境変数が本番に入っている必要がある）。
